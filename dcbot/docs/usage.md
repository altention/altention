# 機器人使用說明（完整版）
> 給 agent 讀的參考：使用者問用法時照這份回答。說明頻道貼的是精簡版 `dcbot/GUIDE.md`。`{{名稱}}` 是因安裝而異的字（見 `dcbot/GUIDE.variables.md`），`{{#名稱}}…{{/名稱}}` 只在有那個值時成立。

這個機器人是 Claude Code 的行動版控制台：你在頻道裡打字，{{bot_machine}} 上的 Claude Code 幫你執行指令、讀寫檔案{{#attach_machines}}、管理其他機器{{/attach_machines}}。

## 基本用法
- **直接打字**：在頻道裡發訊息就是跟 Claude 對話。訊息上出現 👀 表示已經送進 Claude。
- **每個頻道一個獨立對話**。自己新開一個文字頻道時，機器人會先貼一張設定卡：
  - 第一步，要做什麼：🤖 Claude 對話、💻 終端機（一個 shell，見下面「終端機頻道」）、📂 檔案（見下面「看檔案」），或 📝 一般頻道（機器人不回應，拿來記東西；之後要改用 `/setup`）。
  - 第二步，開在哪裡{{#attach_machines}}（可以用上面的下拉選單換機器：{{machines}}；別台機器只能開在你的 tmux）{{/attach_machines}}：🆕 開新的 tmux（填 session 名稱、視窗名稱可留空、工作目錄）、➕ 加到現有的 tmux（選 session，再填視窗名稱、工作目錄）、或 🛠️ 交給機器人管（機器人自己的 tmux）。工作目錄不想用打的，先按 📁 **選工作目錄** 一層層點進去選，之後的選項都會用它。按「← 返回」可以回第一步。
  開在你自己 tmux 的，電腦上 `tmux attach -t <名稱>` 就看得到。設定前發的訊息會等設定好再送出。工作目錄預設是 `{{default_cwd}}`，開在專案分類底下的會預設成那個專案的資料夾。之後要換地方用 `/cwd`。
- **處理中可以補充**：Claude 還在跑的時候再發訊息，會送進同一輪，不用等它結束。不過它要等手上的工具跑完才會看到；急的話在訊息前面加 `!!`（例如 `!!先停下來，改用另一個資料夾`），機器人會按「立刻送出」，正在跑的指令移到背景繼續跑（不能移的會被中斷），Claude 馬上讀到。訊息加上 ⚡ 就是送出了。
- **回覆的樣子**：Claude 中途說的話會以引用樣式即時出現；每輪最後一則是正式回覆，下面的灰字是用了哪些工具、花了幾秒，和 context window 用了多少（例如 `context 20%`，滿了之前可以 `/compact` 或 `/reset`）。`/status` 也看得到確切的 token 數。
- **通知**：中途的話、處理中的進度不會響；正式回覆、提問、計畫和出錯才會響。跑超過 10 分鐘的一輪，結束時會 @ 你，頻道靜音也收得到。
- **API 出錯**（用量上限、伺服器忙、登入失效）：頻道會貼出原因和「再試一次」按鈕，按了 Claude 會從中斷的地方接著做。
- **看完整過程**：在 Claude 的回覆加上 📋 表情符號，機器人會在那則回覆底下開一個討論串，放這一輪的完整過程：你問了什麼、它中途說的話、每個工具呼叫（指令、讀寫哪個檔案）和它的輸出。不加就不會出現任何東西。 太長的段落只先放開頭，那一則訊息的最後一行會寫「…（還有 N 字，對這則按 📋 接著看）」：在**討論串裡對那一則**再按一次 📋，就接著貼後面最多一萬字（還有的話最後一則會再有同樣的一行，可以一直按到貼完）。
- **附件**：圖片和檔案直接傳，Claude 讀得到（可以只傳圖不打字）。
- **背景工作**：叫 Claude 在背景跑的東西會跨輪存活，跑完它會自己回一則訊息報告結果。
- **機器人重啟不影響對話**：Claude 活在 tmux 裡，部署新版本時對話和背景工作都照常。重啟那十幾秒裡你發的訊息，機器人回來後會自動補送（標「🔁 補送」）；離線超過 30 分鐘的訊息不會自動送，只會列出來請你重發。

## Claude 要你回應時、跨頻道
- **Claude 問你問題**：需要你從幾個選項裡挑的時候，會出現按鈕（可複選的是下拉選單，選好後點選單外面送出）。想回答選項以外的內容，按「其他…」或直接在頻道打字都可以（只剩一題沒答時，打的字就是那題的答案，訊息會加上 ✅）。一次問好幾題時，全部答完 Claude 才會繼續。
- **終端機跳出選單時**：Claude Code 需要你按選項（權限確認、舊對話裡的計畫核准、選擇器）時，頻道會貼出那個選單的畫面，每個選項一顆按鈕，另有「輸入文字…」、Enter、Esc。選項會變成輸入框的（例如「告訴 Claude 要改什麼」），先按那個選項，再按「輸入文字…」。按下去之前機器人會重讀畫面，選單已經換成別的（終端機那邊答掉了、換了一題）就不送，改貼現在的畫面。auto mode 下遇到危險的刪除（例如 `rm -rf` 到重要的路徑），Claude Code 只給約 2 分鐘：訊息下面會寫多久後自動拒絕，時間到就當作拒絕、對話照常往下走，之後再按按鈕不會送出。
- **計畫要你核准**：Claude 用 plan mode 寫好計畫時，計畫會貼到頻道，下面有「核准，開始執行」和「要修改…」兩顆按鈕。按「要修改…」可以寫下要改什麼，Claude 改完會再貼一次。
- **子代理和 workflow**：Claude 派出子代理時，頻道裡會出現一則狀態訊息（⏳ 執行中 → ✅ 完成），底下掛一個討論串，裡面是它收到的任務、過程中做了什麼、最後的結果。Workflow 是整個一串，裡面有每個代理的開始和結果。跑完的討論串會自動收起來，從狀態訊息還是點得進去。討論串只是紀錄，在裡面打字不會送給 Claude。
- **轉發別的頻道的訊息**：用 Discord 的「轉發」把訊息丟進來，Claude 會看到原文（含附件）；轉發後幾秒內接著打的話會跟它合在一起送出，例如轉發一則再說「看一下這個」。
- **叫 Claude 把東西貼到別的頻道，或跟別的頻道的 Claude 說話**：例如「整理成報告貼到 #reports」、「把問題報告給 {{example_channel_a}}」。貼出來的訊息是一張卡片，上面標「📨 來自 #xxx」，每個寄件頻道一個固定顏色，跟這個頻道 Claude 自己的回覆（一般文字）分得開；對方頻道有 Claude 的話，它會收到，也知道怎麼回覆。如果它在處理別的頻道傳來的事時用按鈕問你問題，傳話過來的那個頻道會出現「⏸️ #xxx 的 Claude 在等你回答問題」和連結（會響），你回答後那行會變成 ✅。頻道名稱打錯或頻道改過名時會報錯並提示相近的頻道，不會再自動多開一個；真的要新開紀錄頻道時它會加 `--create`。**頻道可以放心改名**：機器人和排程都用頻道 ID 認頻道，改名後那個頻道的 Claude 下一則訊息會被告知新名字。也可以叫它在某個頻道放「看板」{{#example_board}}（例如 {{example_board}}）{{/example_board}}：同一則訊息原地更新，頻道裡只留最新的樣子。兩個 Claude 連續來回到上限（預設 10 次；安裝時選的次數寫在實例 `plugins.json` 的 `dcbot.talk_limit`，0 是不限制）你都沒插話，機器人會先暫停並 @ 你問要不要繼續（可以按「這兩個頻道不再限制」）；傳話的那個 Claude 也會被告知在等你決定，不會空等或重送。要讓它們長時間討論，用 `/talklimit <次數>` 或 `/talklimit off` 調整這個頻道的上限。
- **叫 Claude 去看別的頻道**：說「去看 #某頻道」就行。每個 Claude 都知道用 `altention dc read` 讀頻道訊息、討論串和那個頻道背後 Claude 的對話。
- **回覆某則訊息**：用 Discord 的「回覆」功能回某則訊息時，被回覆的內容會一起交給 Claude，可以直接說「這個」。

## 指令
平常打 `/` 從選單選；選單叫不出來時，有 `!` 版本的直接打成一般訊息也一樣。其他 `!` 開頭的字不會送給 Claude（`!!` 開頭的急件除外）。
- `/status`, `!status`: 機器人版本、這個頻道的模式、工作目錄、對話編號、tmux 名稱。
- `/reset`, `!reset`: 這個頻道開新對話。舊對話不會消失，可以用 `/resume` 接回。
- `/resume`, `!resume`: 列出最近的對話，選一個接回（會把那個對話的紀錄貼進頻道）。`!resume <id 開頭 8 碼>` 可以接回清單外更舊的。選好之後下一則訊息接回它；貼紀錄像 `/attach` 一樣不發通知，長的要貼幾分鐘；這個頻道貼過的對話不會重貼，只放最後幾輪。在對話裡直接打 Claude Code 的 `/resume` 也一樣。
- `/stop`, `!stop`: 中止正在跑的工作，對話保留。
- `/recap`, `!recap`: 顯示這個頻道的對話最近幾輪（預設 3 輪，最多 20），內容直接讀 Claude 的對話紀錄。
- `/screen`, `!screen`: 看 Claude 的終端機畫面（圖片，按 📝 看文字）。圖片保留顏色和對齊；📝 會回一則文字版，可以複製。
- `/key`, `!key`: 送按鍵到終端機，例如 `Escape`、`Enter`、`Down Enter`。
- `/mode`, `!mode`: 切換 `tmux`（預設，常駐對話）或 `print`（每則訊息跑一次，備用）。
- `/cwd`, `!cwd`: 設定這個頻道的工作目錄，會開新對話。
- `/files`, `!files`: 檔案瀏覽器（見「看檔案」）。
- `/rename`, `!rename`: 頻道和 Claude Code 的對話一起改名。
- `/setup`, `!setup`: 重新叫出這個頻道的設定卡。
- `/attach`, `!attach`: 把 tmux 裡自己開的 Claude Code 接到頻道（見「接上你自己開的對話」）。
- `/detach`, `!detach`: Discord 不再跟著這個對話，對話本身不受影響，頻道移到封存。
- `/talklimit`, `!talklimit`: 這個頻道的 Claude 跟別的頻道最多連續來回幾次（`off` 不限制）。
- `/commands`, `!commands`: 列出 Claude Code 的指令和 skill；`refresh` 重新整理選單。
- `/run`: 終端機頻道執行一行指令，可以從跑過的指令裡搜尋（見「終端機頻道」）。
- `!help`: 列出機器人的指令。
- `!restart`: 重啟機器人。
- `!rollback`: 退回上一個正常版本。

## Claude Code 的指令和 skill
Claude Code 自己的 `/` 指令和 skill 也在選單裡，打 `/` 加幾個字就能搜尋。這些只能用 `/`，會送進 Claude。
- **Skill**：{{skill_examples}} 等。`args` 欄填要交給它的內容，例如 `/deep-research` 的研究主題。結果照常貼在頻道。
- **常用指令**：`/usage`（用量）、`/context`（context 佔用）、`/compact`（壓縮對話）、`/model`（`args` 填 `opus`、`sonnet` 之類就直接切換）、`/effort`、`/fast`、`/init`、`/security-review`。
- `/btw <問題>`：順便問一句。會開一個討論串回答，在討論串裡直接打字就是追問（前面的問答會一起帶上）。它看得到目前的對話，不會打斷正在跑的工作，問答也不會留在主對話裡。
- `/tour`：上手導覽，一步步帶你試主要功能。`args` 寫一項就只帶那一項（例如 `/tour 提醒`）。這個 skill 在引擎的 `skills/tour`。
- `/doctor` 是 Claude Code 自己的安裝檢查；Altention 的系統檢查（`altention doctor`）請跟 Claude 說「跑系統檢查」。
- `/cc`：執行選單裡沒有的任何 Claude Code 指令，`command` 欄可以打字搜尋。
- `/commands`：列出全部；裝了新的 skill 之後用 `/commands refresh:True` 更新選單（平常每天自動更新一次）。
- 不要某個 skill：把它所屬的插件在這台關掉（`disabled_on`）。只刪 `~/.claude/skills` 裡的連結，同步會在 15 分鐘內補回來。
- 會開面板的指令（例如 `/usage`、不帶參數的 `/model`）送出後會貼回畫面，並依面板最下面那行提示（例如「Enter to set as default · s to use this session only · Esc to cancel」）附上按鈕，按鈕只送提示上寫的鍵；看不出提示時用 `/key` 操作。面板會在你發下一則訊息時自動關掉。
- 也可以照舊把指令當成一般訊息打出來送出，效果相同。

## 接上你自己開的對話
你在 {{bot_machine}} 的 tmux 裡自己開的 Claude Code，可以原地接到一個頻道，不用重開。
- `/attach`：在任何頻道下都可以，不用自己先開頻道，也不用填參數。它會列出這台機器 tmux 裡正在跑的 Claude Code，每個對話下面有一顆按鈕；點一下，機器人就在「專案名稱」的分類下開好頻道並接上（專案名稱取自 git repo 或資料夾的名字）。例外：在一個剛開、還沒設定的頻道裡用 `/attach`，就直接接在這個頻道，不另開。
- 一次接上整個專案：清單裡有「📁 整個專案 …」的按鈕（同一個專案有兩個以上還沒接的對話時才會出現），不管它們開在哪個 tmux 裡都會一起接上。
- 頻道名稱是「tmux 名稱-視窗」，同一個 tmux 的視窗會排在一起；視窗有自己取名字就用名字，否則用編號。
- 接上時，機器人會把那個對話之前的完整內容貼進頻道（每一輪你打的話和 Claude 的最後回覆，不截短、不發通知）。長的對話有上百則，大約一秒貼一則，貼完有結尾標記；這段期間頻道照常可以用。
- 清單上的按鈕 15 分鐘後失效，點過一次也會消失，放著不管不會有事。
- 接上之後兩邊同時可用：在頻道打字會送進那個對話；你在終端機打的內容和 Claude 的回覆，頻道裡也看得到。
- Claude 用按鈕問問題時，題目會出現在頻道而不是終端機。
- `/detach`：在那個頻道裡下，意思是「Discord 不再跟著這個對話」，不會關掉任何東西（設定卡開的視窗也一樣，之後它就只是你 tmux 裡的一個普通視窗）。對話本身完全不受影響，繼續在你的 tmux 裡跑；頻道移到「封存」分類，機器人不再處理裡面的訊息。在封存的頻道裡打字，會出現兩顆按鈕：「接回原本的對話」（原本的視窗不在了，會在同一個 tmux session 開新視窗接回；已經接在別的頻道時會先問你要不要移過來）和「在這裡開新對話」（跳設定卡）。之後對同一個 tmux 視窗再 `/attach`，也會把封存的頻道搬回來沿用，歷史訊息都在。同一個對話同時只會接在一個頻道。
- Claude 在終端機那邊結束時頻道會通知；在同一個 tmux 窗格重新開 Claude，會自動接回同一個頻道。
- 刪掉頻道不會關掉 Claude：它照樣在 tmux 裡跑，`#audit` 會記下它在哪裡，要關請自己關，或用 `/attach` 接到新頻道。機器人開的視窗被你在電腦上關掉的話，下一則訊息會在同一個 tmux session 重開並接回對話。
- 條件：那個 Claude 必須是在 tmux 裡開的。直接開在終端機裡的對話接不上，要先在 tmux 裡用 `claude --resume` 重開。
- 接上的頻道不能用 `/reset`、`/resume`、`/cwd`、`/mode`，那是你自己的終端機，機器人不會關它；要清空對話直接發 `/clear`。
- **對話之間互相討論**：在訊息裡用頻道提及（打 `#` 選頻道），例如在 {{example_channel_b}} 說「先看看專案，再把問題報告給 {{example_channel_a}}」。Claude 會用 `altention dc post` 貼過去，那裡的 Claude 會收到；來往在兩個頻道都看得到。
- `/rename <名字>`：頻道和 Claude Code 的對話一起改名。來源（哪台機器、哪個 tmux 視窗、哪個資料夾）照舊寫在頻道主題和 `/status`。
{{#attach_machines}}- **別台機器**：`/attach` 也會列出 {{attach_machines}} 上 tmux 裡的 Claude（會標出機器名稱），接上之後用起來一樣。之後要加別台，在機器清單給它 `dcattach` 角色就行（那台要能從 {{bot_machine}} 用 SSH 連到）。別台機器的對話目前還不支援 📋 看過程。{{/attach_machines}}{{^attach_machines}}- **別台機器**：別台機器 tmux 裡的 Claude 也能接上。在機器清單加上那台並給它 `dcattach` 角色（那台要能從 {{bot_machine}} 用 SSH 連到），`/attach` 就會列出它。別台機器的對話目前還不支援 📋 看過程。{{/attach_machines}}

## 終端機頻道
設定卡選 💻 的頻道是一個真的 shell（你的 zsh 和設定都在），開在你的 tmux 裡。
- 每則訊息就是一行指令（多行就是依序執行多個指令）。輸出貼成一個程式碼區塊，跑的時候每幾秒更新，結束時標示結束碼；輸出很長時另外附完整的檔案。
- 每則輸出下面有 Ctrl-C、🔁 再跑一次、📺 畫面。
- 指令還在跑時再發的訊息，會當成輸入打給它（例如回答 y/n、輸入密碼）。
- `/run`：在指令欄打幾個字，會列出這個頻道跑過、符合的指令可以直接點。shell 自己的 `!!`、`history` 也照樣能用。
- `/stop` 送 Ctrl-C；`/screen` 看整個畫面；`/reset` 關掉這個 shell，下次打指令會開一個新的。
- 打什麼就跑什麼，沒有確認。`vim`、`htop` 這類全螢幕程式不適合在這裡用。

## 看檔案
- `/files`（或 `!files [路徑]`）：在任何頻道叫出檔案瀏覽器，從這個頻道的資料夾開始，在這個頻道所在的機器上{{#example_machine}}（{{example_machine}} 頻道就看 {{example_machine}} 的檔案）{{/example_machine}}。只有一則訊息，點了原地更新，看完按 ✖ 關掉。
- **資料夾**：清單在程式碼區塊裡（資料夾在前，附大小或項目數，`M`／`?` 是 git 改過／新檔），下拉選單點一下就進資料夾或打開檔案。一頁 25 項，多的用 ◀ ▶ 換頁，或按 🔍 打檔名的幾個字找（例如 `tmux br`，會找整個資料夾底下）。⬆ 上層、🏠 回起點、👁 顯示隱藏檔。
- **檔案**：一頁幾十行，有行號、依副檔名上色；◀ ▶ 翻頁、↧ 跳到第幾行、📎 把整個檔案當附件傳（手機可以直接開）。圖片直接顯示；Markdown 可以切成 📖 排版後的樣子。
- **Claude 提到的檔案**：Claude 的回覆裡提到的檔案（例如 `bot/setup.py:142`），回覆下面會有 📂 按鈕，點了直接打開到那一行。
- **📂 檔案頻道**：設定卡選 📂，選機器和資料夾（點選或打路徑），這個頻道就是那個資料夾的瀏覽器，一直都在。直接打字就是找檔案；打路徑（可以加 `:行號`）就跳過去。瀏覽器會移到最下面。
- 只能看不能改，要改請叫 Claude。放金鑰和 token 的地方（`~/.config`、`~/.ssh`、`.env`、金鑰檔等）不會顯示，連檔名都不會出現。

## 出狀況時
1. **沒反應，或出現「⚠️ 訊息可能沒有送進 Claude」**：先 `/screen` 看畫面。卡在面板或選單就 `/key Escape`，再重發訊息。
2. **跑太久或方向錯了**：`/stop`，然後直接說要怎麼改。
3. **對話整個亂掉**：`/reset` 開新的；想回去用 `/resume`。
4. **tmux 模式本身有問題**：`!mode print` 切到備用模式，對話會接續。
5. **新版本壞掉**：新版本 3 分鐘內沒上線會自動退回上一版；也可以手動 `!rollback`。
6. **想自己接手**：SSH 到 {{bot_machine}} 執行 `tmux -L dcbot attach -t <名稱>`，名稱看 `/status`。

## 已知限制
- 補充訊息要等 Claude 手上那個工具跑完才會被看到；急的話加 `!!` 立刻送出。
- `/btw` 的各個討論串大致是分開的，但 Claude Code 會記得「上一個 btw 問題」，所以剛換到另一個討論串的第一題，偶爾還會參考到前一個討論串的最後一題。
- Claude 用按鈕問問題時會一直等你回答（最多 12 小時）。只剩一題時，打字就是回答；還有好幾題沒答時，打的字要等全部答完才會被看到。不想答就 `/stop`。計畫核准只能用按鈕。
- `/reset`、`/cwd`、`/resume` 切換對話、`/mode` 切換模式，都會結束該對話裡的背景工作。
- 機器重開後 tmux 對話會消失：機器人會在頻道通知，下一則訊息自動接回對話，但當時在跑的工作和背景工作會中斷。要長期跑的服務請 Claude 做成 systemd 服務。
- 多個頻道用同一個工作目錄時，同時改檔案或 commit 會互相衝突。
- 對話開在別台機器的頻道：`/resume` 的選單不會列出可選的對話（Discord 要馬上回應，來不及問那台）；請用 `!resume` 看編號清單，再 `!resume <編號或 id 開頭>` 接回。
- 別台機器上的對話，機器人是用 ssh 進去讀那台預設位置（`~/.claude`）的對話檔。那台的 Claude Code 若用了自訂的 `CLAUDE_CONFIG_DIR`，📋（展開一輪）和 `/resume` 之後貼的對話紀錄會讀不到，頻道會說那台不給讀；回覆本身不受影響。
- 終端機裡輸入框空的時候按「←」會進到 Claude Code 的背景對話清單，原本的對話搬到背景繼續跑，頻道照樣收得到它的回覆；按 Esc 就回到原本的對話。清單畫面上機器人不會替你打字（接上的窗格請你自己按 Esc；機器人開的對話它會先按一次 Esc）。限制：在清單裡直接打字會開一個**全新的背景對話，沒有任何頻道跟著它**；窗格正在看那種對話、而畫面最上面的標頭已經捲走時，從 Discord 發的訊息會進到它而不是這個頻道的對話（等不到回覆時機器人會提醒你到終端機確認）。`/bg` 把對話整個丟到背景後，頻道也跟不到那一份：下一則訊息接回的是原本的對話。對話搬到背景之後把視窗或窗格關掉，那個對話還會留在 Claude Code 的背景裡；頻道的下一則訊息接不回它、會開新的對話，要找回它請在終端機用 `claude attach <對話 id>`。
- `/attach` 或 `/resume` 貼對話紀錄的那段期間照常可以打字；這時到的即時訊息和回覆會出現在「以下是…」和「以上是…」兩個標記之間，內容不會少。
- 對話搬到背景又回來後，窗格窄於約 80 欄時可能被誤判成不在忙：回覆照樣會貼，但這段期間 `!stop` 會說沒有正在跑的工作、停不了那一輪。有背景 shell 時狀態列較短，約 70 欄以上不受影響。沒搬過背景的對話，窄於約 70 欄時也可能讀不到在忙（60 欄量過）。
- 閒置 12 小時、沒有背景工作的對話會被關掉省資源，下一則訊息自動接回。
- Claude 執行指令不會逐次問你同意。刪頻道、刪檔、強制推送這類動作，它會先在對話裡問。
- 附件上限 100 MB，存在 {{bot_machine}} 上，14 天後自動刪除。
- 輸入框裡有字、訊息送不出去時，提示的 `/key C-u` 只清得掉游標所在那一行，多行或游標不在行尾時清不完。先用 `/screen` 看：Claude 沒在跑時，`/key C-c` 按一次就能全部清掉，但不要連按（一秒內按兩次會關掉 Claude）；Claude 正在跑時按 `C-c` 會中斷那一輪。

## 秘密和遮蔽
- 機器人的 token 和 SSH 私鑰（公開金鑰、`~/.ssh/config`、`known_hosts`、`authorized_keys` 不算），以及你在實例 `plugins.json` 的 `core.secret_paths` 加的路徑，不會被任何 Claude 讀到：每台機器的每個 Claude（包括你自己開、再 `/attach` 的）要讀、改、搜尋這些檔（或搜尋裝著它們的資料夾，例如 `~/.config`、`~/.ssh`），或下的指令裡寫了這些路徑（含 `$HOME`、`~`、萬用字元的寫法；就算只是要印出或貼出的文字），都會被擋下並說明原因。`ssh -i`、`ssh-add`、`ssh-keygen -y` 這類使用鑰匙的指令放行。這是盡力而為的守門，不是隔離：擋不到 `cd` 之後用相對路徑、以整個家目錄為範圍的搜尋、執行時才拼出的路徑、另寫程式去開檔；token 檔另有 600 權限。要整個關掉，設 `core.secret_guard` 為 false。
- 貼到 Discord 的 Claude 文字和工具輸出裡，像金鑰、token、私鑰的字會換成 `[REDACTED]`，並加一行小字說遮了幾處（雜湊、ID 不遮）。`/screen` 和選單畫面是畫面本身，不在內。

## 改機器人說的話
- 訊息沒送出時機器人說的那些句子（「⚠️ 終端機現在不是一般的輸入框…」之類）可以換成你自己的說法：在實例的 `plugins.json` 加 `dcbot.text`，一句一個鍵，例如 `{"dcbot": {"text": {"not_sent.claude_code.dialog": "有對話框開著，這則沒送出。"}}}`。存檔後最多一分鐘生效，不用重啟。
- 鍵是「組.代號」。組有 `not_sent`（沒送出）、`unconfirmed`（送了但沒等到回音）、`notes`（順帶說的，例如「已經重送」）、`cleared`、`far`（那台機器連不上時說的）。全部的代號和預設的句子在 `dcbot/bot/messages.py`；原句裡的 `{text}`、`{screen}` 這類是會代進去的內容，照樣寫在你的句子裡就會出現。
- 寫錯不會壞：值不是文字的那一鍵不算；`plugins.json` 整個讀不到時用預設的句子。目前只有這一類句子能改，其他的之後才會搬過去。
