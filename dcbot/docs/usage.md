# 機器人使用說明（完整版）
> 給 agent 讀的參考：使用者問用法時照這份回答。說明頻道貼的是精簡版 `dcbot/GUIDE.md`。`{{名稱}}` 是因安裝而異的字（見 `dcbot/GUIDE.variables.md`），`{{#名稱}}…{{/名稱}}` 只在有那個值時成立。

這個機器人是 Claude Code 的行動版控制台：你在頻道裡打字，{{bot_machine}} 上的 Claude Code 幫你執行指令、讀寫檔案{{#attach_machines}}、管理其他機器{{/attach_machines}}。

## 基本用法
- **直接打字**：在頻道裡發訊息就是跟 Claude 對話。訊息上出現 👀 表示已經送進 Claude。
- **每個頻道一個獨立對話**。自己新開一個文字頻道時，機器人會先貼一張設定卡：
  - 第一步，要做什麼：🤖 Claude 對話、💻 終端機（一個 shell，見下面「終端機頻道」）、📂 檔案（見下面「看檔案」），或 📝 一般頻道（機器人不回應，拿來記東西；之後要改用 `/setup`）。
  - 第二步，開在哪裡{{#attach_machines}}（可以用上面的下拉選單換機器：{{machines}}；別台機器只能開在你的 tmux）{{/attach_machines}}：🆕 開新的 tmux（填 session 名稱、視窗名稱可留空、工作目錄）、➕ 加到現有的 tmux（選 session，再填視窗名稱、工作目錄）、或 🛠️ 交給機器人管（機器人自己的 tmux）。工作目錄不想用打的，先按 📁 **選工作目錄** 一層層點進去選，之後的選項都會用它。按「← 返回」可以回第一步。
  開在你自己 tmux 的，電腦上 `tmux attach -t <名稱>` 就看得到。設定前發的訊息會等設定好再送出。工作目錄預設是 `{{default_cwd}}`，開在專案分類底下的會預設成那個專案的資料夾。之後要換地方用 `/cwd`。
- **處理中可以補充**：Claude 還在跑的時候再發訊息，會送進同一輪，不用等它結束。不過它要等手上的工具跑完才會看到；急的話在訊息前面加 `!!`（例如 `!!先停下來，改用另一個資料夾`），機器人會按「立刻送出」，正在跑的指令移到背景繼續跑（不能移的會被中斷），Claude 馬上讀到。訊息加上 ⚡ 就是送出了。
- **回覆的樣子**：Claude 中途說的話會以引用樣式即時出現；每輪最後一則是正式回覆，下面的灰字是用了哪些工具、花了幾秒，和 context window 用了多少（例如 `context 20%`，滿了之前可以 `/compact` 或 `/reset`）。`/status` 也看得到確切的 token 數。
- **通知**：中途的話、處理中的進度不會響；正式回覆、提問、計畫和出錯才會響。真的需要你的時候才會 @ 你：Claude 用按鈕問你、計畫等你核准、權限選單、兩個 Claude 來回到上限、出錯要你處理，或 Claude 說要跟你討論。用量到上限、登入失效、機器人退回舊版、別台連不上這種整個系統卡住的事，只在通知頻道 @ 一次。
- **API 出錯**（伺服器忙、登入失效）：頻道會貼出原因和「再試一次」按鈕，按了 Claude 會從中斷的地方接著做。
- **用量達到上限**：Claude Code 自己會在用量重置後接著做（它的設定「Continue automatically at usage limit」，預設開著）。這時頻道貼「⏸️ 用量達到上限，Claude Code 會在 <時間> 自己接著做」，不放「再試一次」：在那個頻道打字會先送出你的訊息，等待就取消了（多半也會再撞上限）。重置後那則改成「▶️ 用量重置了，Claude 接著做」。時間會換成你的當地時間；對話在別台機器上時，照那台畫面上的字顯示，是那台機器的時間。Claude Code 沒在等時（設定關掉、重置在 24 小時以後），照舊貼「中斷了」和「再試一次」。要有人按 Enter 時（例如電腦睡著過）會說，可以用 `/key Enter`。等的期間，那個視窗不會因為閒置被關掉。
- **卡住的頻道**：status 看板「在等你的事」那則下面，列出暫時卡住的頻道（用量上限、API 錯誤，之後還有登入失效）；終端機的對話框跟提問列在一起。
- **看完整過程**：在 Claude 的回覆加上 📋 表情符號，機器人會在那則回覆底下開一個討論串，放這一輪的完整過程：你問了什麼、它中途說的話、每個工具呼叫（指令、讀寫哪個檔案）和它的輸出。不加就不會出現任何東西。 太長的段落只先放開頭，那一則訊息的最後一行會寫「…（還有 N 字，對這則按 📋 接著看）」：在**討論串裡對那一則**再按一次 📋，就接著貼後面最多一萬字（還有的話最後一則會再有同樣的一行，可以一直按到貼完）。
- **附件**：圖片和檔案直接傳，Claude 讀得到（可以只傳圖不打字）。機器人開的 Claude 讀附件不會先問。用 /attach 接上的（你自己開的 Claude Code）讀附件時，可能會問能不能讀工作目錄外的檔案：選「Yes, and keep allowing any reads outside the working directories」就好。不要選「No, and block reads outside the working directories from now on」：選了之後，每個專案都讀不到工作目錄外的檔案，附件也讀不到；選錯了的話，把 ~/.claude/settings.json 裡的 blockReadsOutsideWorkingDirectories 那行刪掉。
- **回覆裡的表格**：Discord 不顯示 Markdown 表格（會變成一堆 `|`），所以正式回覆裡的小表格（最多 5 欄、20 列）貼出前會自動改寫：全是英數字、夠窄的變成對齊的程式碼區塊；有中文、全形字或太寬的變成清單，每列一項（「- **第一欄**：表頭2 值2；表頭3 值3」）。更大的表格、程式碼區塊裡的表格照原樣。不想要這個改寫：在實例 `plugins.json` 寫 `"dcbot": {"small_tables": false}`。
- **公式、表格、流程圖畫成圖**：裝了會畫圖的插件、而且在機器人那台開著時，Claude 的正式回覆裡有獨立的公式、表格或 mermaid 流程圖，貼出前會交給插件，把那幾塊畫成圖，跟文字照順序貼出；超過幾秒時頻道會先出現一行「⏳ 整理排版中…」，貼好就消失。插件失敗或超時（最多 60 秒）就照上一項的方式貼。這段時間這個頻道後面的訊息會等它貼完才出來，順序不會亂。不想要就在那台關掉那個插件。
- **看圖是從什麼畫出來的（按 📝）**：機器人貼出的圖如果是插件畫的、插件也附上了原文（公式的 LaTeX、流程圖的 mermaid、圖表的程式…），在那則訊息按 📝，機器人會回「<是什麼>，<用什麼工具> 做的」和原文的程式碼區塊，可以複製來改；太長的改附成檔案，同一則裡幾張圖出自同一份原文時只回一次（「第 1–3 張：」）。機器人不會先在訊息上加 📝，要自己加；沒附原文的圖按了不會有反應。原文最多保留 30 天（最多 500 則訊息），存之前會先遮掉像金鑰、token 的字。
- **背景工作**：叫 Claude 在背景跑的東西會跨輪存活，跑完它會自己回一則訊息報告結果。
- **機器人重啟不影響對話**：Claude 活在 tmux 裡，部署新版本時對話和背景工作都照常。重啟那十幾秒裡你發的訊息，機器人回來後會自動補送（標「🔁 補送」）；網路斷線一陣子、重新連上 Discord 後也一樣補送；但指令只補做只看不改的那幾個（`!help`、`!status`、`!recap`、`!screen`、`/btw`），其他指令（例如 `!restart`、`!key`、`!cwd`、`/clear`）不會補做，頻道會說哪一則沒執行，要的話再送一次；終端機頻道離線時收到的 shell 指令一律不補跑；離線超過 30 分鐘的訊息不會自動送，只會列出來請你重發。

## Claude 要你回應時、跨頻道
- **Claude 問你問題**：需要你從幾個選項裡挑的時候，會出現按鈕（可複選的是下拉選單，選好後點選單外面送出）。想回答選項以外的內容，按「其他…」或直接在頻道打字都可以（只剩一題沒答時，打的字就是那題的答案，訊息會加上 ✅）。一次問好幾題時，全部答完 Claude 才會繼續。
- **終端機跳出選單時**：Claude Code 需要你按選項（權限確認、舊對話裡的計畫核准、選擇器）時，頻道會貼出那個選單的畫面，每個選項一顆按鈕，另有「輸入文字…」、Enter、Esc。選項會變成輸入框的（例如「告訴 Claude 要改什麼」），先按那個選項，再按「輸入文字…」。按下去之前機器人會重讀畫面，選單已經換成別的（終端機那邊答掉了、換了一題）就不送，改貼現在的畫面。auto mode 下遇到危險的刪除（例如 `rm -rf` 到重要的路徑），Claude Code 只給約 2 分鐘：訊息下面會寫多久後自動拒絕，時間到就當作拒絕、對話照常往下走，之後再按按鈕不會送出。新開的對話第一次啟動時，如果那個資料夾的 CLAUDE.md 引用了資料夾外面的檔案（外部插件常這樣做），Claude Code 會先問要不要讀那些檔案：頻道會貼出這個問題和兩顆按鈕，你選之前 Claude 會停在那裡（最多等 30 分鐘）。只有你信任那些檔案時才選 Yes；每個資料夾只問一次。
- **訊息沒送進去時**：終端機開著對話框、你在終端機打字打到一半、或那台連不上時，機器人不會硬打字，頻道會說「這則沒有送出」並附一顆「再送一次」按鈕：處理好之後按它，原文會重新送進去（24 小時內有效）。別的頻道的 Claude 用 `altention dc post` 傳來的訊息不用你按：對話框關掉、終端機回到一般輸入框之後，機器人會照原本的順序自動補交，並在那則下面說「已補送」；24 小時內都補不進去就放棄，並告訴傳來的那個頻道。你自己打的訊息不會自動補（你可能已經重打了）。
- **計畫要你核准**：Claude 用 plan mode 寫好計畫時，計畫會貼到頻道，下面有「核准，開始執行」和「要修改…」兩顆按鈕。按「要修改…」可以寫下要改什麼，Claude 改完會再貼一次。
- **子代理和 workflow**：Claude 派出子代理時，頻道裡會出現一則狀態訊息（⏳ 執行中 → ✅ 完成），底下掛一個討論串，裡面是它收到的任務、過程中做了什麼、最後的結果。Workflow 是整個一串，裡面有每個代理的開始和結果。跑完的討論串會自動收起來，從狀態訊息還是點得進去。討論串只是紀錄，在裡面打字不會送給 Claude。
- **轉發別的頻道的訊息**：用 Discord 的「轉發」把訊息丟進來，Claude 會看到原文（含附件）；轉發後幾秒內接著打的話會跟它合在一起送出，例如轉發一則再說「看一下這個」。
- **叫 Claude 把東西貼到別的頻道，或跟別的頻道的 Claude 說話**：例如「整理成報告貼到 #reports」、「把問題報告給 {{example_channel_a}}」。貼出來的訊息是一張卡片，上面標「📨 來自 #xxx」，每個寄件頻道一個固定顏色，跟這個頻道 Claude 自己的回覆（一般文字）分得開；對方頻道有 Claude 的話，它會收到，也知道怎麼回覆。如果它在處理別的頻道傳來的事時用按鈕問你問題，傳話過來的那個頻道會出現「⏸️ #xxx 的 Claude 在等你回答問題」（計畫是「在等你核准計畫」）和連結（會響），你回答、核准或退回計畫後那行會變成 ✅。頻道名稱打錯或頻道改過名時會報錯並提示相近的頻道，不會再自動多開一個；真的要新開紀錄頻道時它會加 `--create`。**頻道可以放心改名**：機器人和排程都用頻道 ID 認頻道，改名後那個頻道的 Claude 下一則訊息會被告知新名字。也可以叫它在某個頻道放「看板」{{#example_board}}（例如 {{example_board}}）{{/example_board}}：同一則訊息原地更新，頻道裡只留最新的樣子。Claude 貼回**自己的頻道**時（例如回答裡有一張 Discord 顯示不了、另外畫成圖的表格）不包卡片，就是一般的文字加圖片，跟它的回覆一樣；一則最多帶 10 個附件（全部加起來 8 MB），附件都在最後一則。同一個 Claude 連續貼到同一個頻道的幾則會照送出的順序出現；交給對方 Claude 是另外排隊的（一則交完才交下一則），對方慢或那台連不上時，Discord 上照樣馬上看得到。交付途中出錯時，寄件的頻道會出現「這則沒交到 #X 的 Claude」。卡片上的「來自」是查出來的：`altention dc post` 會往上找出跑它的 Claude Code，看它是哪個頻道的，不看指令自己帶的環境變數（自稱別的頻道時照查到的送出，並記在 #audit）；不是在 Claude Code 裡跑的（排程、腳本）寫「機器 上的程式（資料夾）」。這是防搞錯和順手冒充，擋不住刻意偽造的程式（都在同一個系統帳號下）。兩個 Claude 連續來回到上限（預設 10 次；安裝時選的次數寫在實例 `plugins.json` 的 `dcbot.talk_limit`，0 是不限制）你都沒插話，機器人會先暫停並 @ 你問要不要繼續（可以按「這兩個頻道不再限制」）；傳話的那個 Claude 也會被告知在等你決定，不會空等或重送。停住的時候又傳來的會排在同一張卡後面（不另外 @ 你，卡片多一行「之後又來了 N 則」），你按「繼續轉交」就照順序全部交出去，按「停下來」就全部不交。停住的訊息會存起來，機器人重啟或換到備援也還在，卡片的按鈕照樣能按。同一個頻道最多留 50 則，再多的不收，傳話的 Claude 會被告知要等你處理那張卡。沒有自己頻道的 Claude（例如終端機裡開的）傳來的也算次數，照這個頻道的上限；排程、腳本傳的不算。要讓它們長時間討論，用 `/talklimit <次數>` 或 `/talklimit off` 調整這個頻道的上限。停住時，兩邊的 Claude 也可以自己讓它繼續一次（`--talk-continue`，帶理由、記在 #audit，同一組頻道一天最多兩次），只放它們這一組的，別的頻道排在同一張卡上的留著等你；「不再限制」和改上限只有你能做。
- **讓某個頻道停到某個時間**（例如「用量到線了，各頻道先停到午夜」）：Claude 用 `altention dc post <頻道> --pause-until 00:00 --why "用量到線"`（時間可以寫 `HH:MM`、`YYYY-MM-DD HH:MM`，或 `30m`、`2h`、`1d`，照實例的時區，最多 7 天）。那個頻道會出現「⏸️ 暫停到 00:00（誰：為什麼）」，那裡的 Claude 也會收到同一段話，做到可以停的地方就停。暫停期間：
  - 你自己在那個頻道說話、按按鈕，照常交給 Claude（暫停照樣留著，到時間照樣叫它）。你說話時（一般訊息，不是「/」指令），已經留著的別的頻道的話會接在你那則後面照順序交給它，到時間恢復就不會再交一次；之後再傳來的照樣留著。
  - 別的頻道的 Claude 傳來的話照樣貼在頻道上（卡片下面寫「暫停中，00:00 恢復時、或使用者在這裡說話時交給 Claude」），先不交給 Claude，最多留 50 則；傳話的那邊會被告知。替你回答（`--answer`）和讓來回上限繼續（`--talk-continue`）會被拒絕，因為那會叫醒它。
  - 到時間機器人會在頻道貼「▶️ 恢復了」並交給 Claude，再照順序把留著的話交給它（每則前面寫暫停期間幾點、誰傳的）；那時機器人沒在跑的，上線後馬上補叫，並寫晚了幾分鐘。要提早恢復：`--unpause --why "…"`。那個頻道自己的 Claude 已經自己讀過留著的話時，可以用 `--drop-held --why "…"` 清掉（別的頻道的 Claude 不行），恢復時就不交了。
  - 每次暫停、改時間、提早恢復、你說話時一起交了幾則、清掉留著的，都記在 #audit；看板「在等你的事」最後有「暫停中的頻道」，`altention dc read --paused` 也會列出來。
- **讓某個頻道開新對話（`--reset`）**：Claude 用 `altention dc post <頻道> --reset --why "為什麼" [--then "新對話的第一句"]`，跟你打 `!reset` 一樣：關掉那個頻道的對話（舊的可以用 `!resume` 接回），不會在它的終端機打 `/clear`。
  - 自己的頻道（例如 context 快滿、寫好交接檔之後）：等這一輪結束才開新對話，接著叫新對話讀交接檔，有 `--then` 就改交那句話。那一輪沒有正常結束（你按 Esc 中斷、或失敗）就開始了新的一輪時，這次 --reset 取消，頻道貼一行小字說明。
  - 別的頻道：只有它閒著（沒在跑一輪、沒有背景工作、子代理或 workflow、沒有排著的訊息）才做，不然拒絕並說原因，沒有強制的選項；暫停中的頻道也拒絕。有 `--then` 就當成那個 Claude 傳來的話交給新對話。
  - 你自己在 tmux 開、接到頻道的對話不適用（只有你能在那裡 `/clear`）。
  - 每次都記在 #audit（誰、為什麼），那個頻道也會貼「🔄 由 #xxx 開了新對話：為什麼」。
- **別的頻道的 Claude 替你回答**：一個頻道卡在等你回答（按鈕提問、終端機的權限選單、計畫核准，還有通知頻道裡「停在舊版 Claude Code」的提醒）時，別的頻道的 Claude 可以替你回答：它先用 `altention dc post <頻道> --waiting` 看在等什麼，再用 `--answer` 回答，走的是跟你按按鈕同一段，所以你已經答了、選單換了、計畫處理過了就不會送；選單上它跟你一樣能按數字、Enter、Esc、方向鍵、Tab、空白或打字。機器人重啟後，還開著的選單會重新接上按鈕（同一張卡，不會再 @ 你一次），所以重啟前問的也還能代答。答了之後卡片的按鈕收起來，下面寫「由 #xxx 的 Claude 回答」，#audit 每次都記一行（包括沒送的和原因）。auto mode 危險刪除前有倒數的那種選單只有你能按。不想讓別的 Claude 代答某個頻道，在那個頻道打 `!agentanswers off`（`!agentanswers on` 打開，預設是開的）；Claude 自己改不了這個設定。
- **發一則任意格式的訊息（`altention dc post --json`）**：Claude、插件、腳本可以把 Discord 支援的一則訊息（文字、embed、Components V2 的框和按鈕、上傳的圖片）原樣發出去：`altention dc post <頻道> --json payload.json`，從任何機器都能用，經機器人送出。它只貼、不交給那個頻道的 Claude。發到別人的頻道時，最上面會加一行小字「📨 來自 #寄件頻道」（V2 是最上面一個文字區塊），放不下就整則不送、說原因，不會截斷；發到自己的頻道或自己頻道的討論串不加。規則跟 `dcctl send-json` 一樣：按鈕的 custom_id 要 `user:` 開頭、不能寫 `@everyone`／`@here`、不能冒用機器人的開頭；只有加 `--mention owner` 時，內容裡你的 `<@ID>` 才會響。`--file` 一起上傳（payload 裡用 `attachment://檔名`）、`--edit <訊息 ID>` 改自己發的（發到別人頻道的照樣留著來源那行；「📨 來自」轉傳卡片不能改，要重新發）、`--thread-new "名稱"` 開討論串發進去、`--reply-to <訊息 ID>` 回覆某則、`--silent` 不推播、`--no-embeds` 不展開連結預覽。預設等 30 秒：送出時印訊息 ID，Discord 或規則不收時說原因（結束碼 4）。一般文字的 `altention dc post` 也能加 `--reply-to` 和 `--silent`。`dcctl send-json <頻道>` 是它的別名（payload 從 stdin 讀）。看板也能用框：`altention dc post <頻道> --board 名稱 --json board.json`，payload 可以是一則或一組（每個一則，最多 10 則），原地更新；不加標題和「更新於」，時間請自己寫在 payload 裡；框改回純文字時會刪掉重貼，釘選跟著移。
- **刪訊息（`altention dc post <頻道> --delete <訊息 ID> [<訊息 ID>…] --why "…"`）**：Claude、插件、腳本可以刪那個頻道裡的任何訊息：機器人的、別的 Claude 的、你的、別人的，一次最多 20 則（多的要分批）。每則刪之前先整則存進 #audit：作者、時間、連結、文字和附件（名字、大小、網址）寫在一則裡，完整內容（embed、元件）附成 .json 檔，文字都先遮罩；讀不到（Discord 沒回應、看不到）或存不進 #audit 的就不刪。已經不在的不算錯。刪的是別人（不是機器人）的訊息時，頻道裡會留一行小字「🗑️ #x 的 Claude 刪了 N 則 @作者 的訊息：理由」，不會響。#audit 裡的不能刪，開了討論串的那一則也不能刪（要收掉請處理那個討論串）；要對訊息所在的頻道下指令。刪的是還在等回答的提問或計畫卡片時，那個提問會取消，提問的 Claude 會收到「卡片被刪了、不是使用者沒理你」；刪的是還開著的終端機選單卡時，畫面上還有那個對話框就馬上重貼一張；看板的一部分、「⏸️ 在等你」的通知、@ 你的「等你」那行，機器人的紀錄也會一起拿掉。一則一則刪，碰到 Discord 的速率限制會等一下再試；時間不夠沒輪到的會在回覆裡列出來，沒有動，再送一次就好。刪別人的訊息要機器人有「管理訊息」權限。刪的是 Discord 上的那一則：別的頻道的 Claude 可能已經讀過了，收不回來。
- **腳本直接送一則訊息（`dcctl send`）**：機器人那台的腳本可以用 `dcctl send <頻道 ID> "…"` 直接送一則，不經機器人的佇列，成功時最後一行是訊息 ID。訊息裡的 `<@…>` 不會 @ 到任何人；加 `--mentions` 只讓內容裡你的 `<@ID>` 會響（真的 @ 到你時，#audit 多記一行是誰 @ 了你；內容沒寫 `<@ID>` 就不會 @），身分組和別人照樣不 @。內容寫了 `@everyone` 或 `@here` 會整則不送（本來就不會響，但看起來像在叫所有人）。超過 2000 字不會截斷：整則不送，結束碼 4，並說「沒有送出：超過 2000 字」。長的請改用 `altention dc post`（會自動分則）。開頭寫成機器人自己用的格式（例如「📨 **來自 #xxx**」「🔔 **[xxx]**」）會被拒絕，免得讀回時被當成別的頻道傳來的或通知；Claude 自己的回覆剛好這樣開頭時照樣貼出，只是讀回時不會被認成那種訊息。每次送出都記在 #audit。Claude 用它發到別人的頻道時，最上面也會加一行小字「📨 來自 #寄件頻道」（跟 `altention dc post --json` 一樣，改的時候會留著）；排程和腳本（不是 Claude 發的）不加。`dcctl edit` 只能改自己發的 post（用 `dcctl send`／`send-json` 發的，含 `altention dc post` 發到自己頻道的純文字；發到別人頻道的改完照樣留著「來自」那行，Claude 在這一版以前發到別人頻道、沒有那行的舊訊息改不了；「📨 來自」轉傳卡片也改不了）：照機器人的訊息紀錄（ledger）判斷，那則要記著、是同一個頻道的 Claude（或同一支程式）發的；別人發的、機器人的卡片和看板都改不了。紀錄每個頻道留最新 500 則，用 `dcctl pin` 釘選的不管多舊都留著（每個頻道最多 50 則）。在 Discord 上手動釘的，要趁它還記著時再跑一次 `dcctl pin` 才算。`dcctl pin` 一則紀錄裡沒有的訊息時照樣釘，但會說它還是不能用 `dcctl edit` 改。寄件人是查出來的，跟 `altention dc post` 一樣：往上找執行它的 Claude Code，照那個 Claude 自己的環境認（它的頻道；沒有頻道就是哪台、哪個資料夾的 Claude；上面沒有 Claude 就是那台的程式），不看指令自己帶的變數。在別台執行時，那台先查好再帶過來（`dcctl whoami` 印出它把你當成誰）。所有 Claude 都在同一個系統帳號底下，所以這只防搞錯和順手冒名，擋不住刻意偽造。被這些規則拒收的（保留的開頭、`@everyone`／`@here`、按鈕的 custom_id、@ 誰、改不是自己發的訊息）結束碼是 4，跟超過 2000 字一樣：沒有送出，重送也沒用。
- **叫 Claude 去看別的頻道**：說「去看 #某頻道」就行。每個 Claude 都知道用 `altention dc read` 讀頻道訊息、討論串和那個頻道背後 Claude 的對話。
- **推播通知（`altention dc notify`）**：Claude 在長時間的工作做完、需要你決定、或出錯時，用 `altention dc notify "訊息"` 推播到預設的通知頻道；`-c <頻道>` 送到別的頻道，那個頻道不存在時改送預設的通知頻道，並註明原本要送哪裡。任何一台都能用。
- **看別台 tmux 的窗格（`altention tmux`）**：`altention tmux list [機器]` 列出各台 tmux 裡的窗格和它們的 `tmux://` 識別碼，`altention tmux read <識別碼> [行數]` 讀那個窗格的畫面，`altention tmux send <識別碼> "文字" [--enter]`（按鍵用 `--keys C-c Enter …`）在那裡打字。Claude 只在你要它做、窗格是它自己開的、或你交給它管的 Claude 卡住時才用。送出前會檢查兩次並先記進 #audit；Claude Code 的窗格只有停在一般輸入框時才收；前景是別的使用者的程式、文字有換行、開頭是 sudo 都會拒絕並說原因。
- **在別台用 `dcctl`**：Discord 的 token 只放在機器人那台。在別台跑 `dcctl`（改主題、封存、列頻道……）時，整個指令會經 ssh 交給機器人那台去做，結果和結束碼原樣傳回來，那台自己的設定檔不會被讀。連不上時會直接說連不上哪一台，不會改用那台自己的 token；連線在指令跑到一半斷掉時不會自動重送（可能已經做了，先看一下再決定要不要再跑一次），`altention dc post`、`read`、`notify` 也一樣。
- **調整頻道和分類的順序**：手機或平板拖不動時，跟 Claude 說例如「把 筆記 這個分類移到 機器人 上面」，它會在機器人那台用 `dcctl position` 調好，並記在 #audit。分類只跟分類排，頻道只在同一個分類裡排；「系統」分類原本在最下面的話會一直留在最下面；你把它移到別處（例如放在自己的分隔分類之間），就照你放的位置，機器人開新分類時也不會再把它拉到最下面。名字用「━」開頭的分類（例如「━━ 專案 ━━」）當成分隔用，不算專案。
- **回覆某則訊息**：用 Discord 的「回覆」功能回某則訊息時，被回覆的內容會一起交給 Claude，可以直接說「這個」。

## 指令
平常打 `/` 從選單選；選單叫不出來時，有 `!` 版本的直接打成一般訊息也一樣。其他 `!` 開頭的字不會送給 Claude（`!!` 開頭的急件除外）。
- `/status`, `!status`: 機器人版本、這個頻道的模式、工作目錄、對話編號、tmux 名稱。
- `/reset`, `!reset`: 這個頻道開新對話。舊對話不會消失，可以用 `/resume` 接回。
- `/resume`, `!resume`: 列出最近的對話，選一個接回（會把那個對話的紀錄貼進頻道）。`!resume <id 開頭 8 碼>` 可以接回清單外更舊的。選好之後下一則訊息接回它；貼紀錄像 `/attach` 一樣不發通知，長的要貼幾分鐘；這個頻道貼過的對話不會重貼，只放最後幾輪。在對話裡直接打 Claude Code 的 `/resume` 也一樣。 這個頻道貼過紀錄、或本來就在這個頻道進行的對話，接回時只貼最後 3 輪。完全不想貼就用 `!resume <id> --quiet`（`/resume` 選單勾 quiet）。
- `/stop`, `!stop`: 中止正在跑的工作，對話保留。
- `/recap`, `!recap`: 顯示這個頻道的對話最近幾輪（預設 3 輪，最多 20），內容直接讀 Claude 的對話紀錄。
- `/where`, `!where`: 這個頻道的 Claude 現在在哪裡：哪台機器、tmux 是機器人的還是你的、哪個 session 和 window（或窗格）、哪個對話（id 開頭和名字）、哪個資料夾，以及改名時哪些會跟著變。卡片下面有〔改名…〕按鈕，按下去填新名字（跟 `/rename` 一樣）；搬家的按鈕之後會加。
- `/screen`, `!screen`: 看 Claude 的終端機畫面（圖片，按 📝 看文字）。圖片保留顏色和對齊；📝 會回一則文字版，可以複製。
- `/key`, `!key`: 送按鍵到終端機，例如 `Escape`、`Enter`、`Down Enter`。
- `/mode`, `!mode`: 切換 `tmux`（預設，常駐對話）或 `print`（每則訊息跑一次，備用）；`!mode retry` 再試一次一般模式。
- `/cwd`, `!cwd`: 設定這個頻道的工作目錄，會開新對話。
- `/files`, `!files`: 檔案瀏覽器（見「看檔案」）。
- `/rename`, `!rename`: 頻道名、Claude Code 的對話名、tmux 的 window 名一起改；session 是機器人替這個頻道開的，也一起改（尾巴的編號留著）。回覆逐項寫 ✅ 改了、❌ 沒改成（附原因，例如 Discord 限制 10 分鐘只能改兩次頻道名）、➖ 這個頻道不適用。在 Discord 手動改頻道名，或在 tmux 用 rename-window 改 window 名，其他的也會照樣跟著變（tmux 依程式自動取的名字不算）。
- `/setup`, `!setup`: 重新叫出這個頻道的設定卡。
- `/attach`, `!attach`: 把 tmux 裡自己開的 Claude Code 接到頻道（見「接上你自己開的對話」）。
- `/detach`, `!detach`: Discord 不再跟著這個對話，對話本身不受影響，頻道移到封存。
- `/archive`, `!archive`: 封存這個頻道（對話、紀錄、看板、檔案、終端機都可以）。機器人開的視窗會關掉，對話留著；你自己接上的對話只是不再跟著，不會關；終端機的 shell 會關掉（有指令在跑時不封存）；紀錄頻道和看板只搬走，插件貼的訊息照樣會貼進來。頻道搬到「封存」分類，主題最前面註明原本在哪個分類、哪天封存的。在封存的頻道打字：那則訊息不會送給 Claude，接回或開新對話後請再送一次；對話頻道會出現「接回原本的對話」「在這裡開新對話」，其他頻道是「恢復這個頻道」，都會搬回原本的分類（分類被刪掉了，就找同名的分類，再沒有才照資料夾推算）。一個分類最多 50 個頻道，滿了會自動開「封存 2」「封存 3」…，空掉的不會自動刪。自己手動搬進「封存」（或舊的「archive」分類）的頻道，機器人下次啟動時會補記，原分類照主題最前面「📦 原分類：X · 封存於 日期」那段讀；12 小時內還在用的對話那次先不動。不會刪掉任何頻道或對話。
- `/talklimit`, `!talklimit`: 這個頻道的 Claude 跟別的頻道最多連續來回幾次（`off` 不限制）。兩個頻道之間用兩邊比較大的那個，所以要兩邊都設。
- `!agentanswers on|off`: 別的頻道的 Claude 能不能替你回答這個頻道的提問、終端機選單和計畫（預設開著；不加字是看現在的設定）。
- `/commands`, `!commands`: 列出 Claude Code 的指令和 skill；`refresh` 重新整理選單。
- `/run`: 終端機頻道執行一行指令，可以從跑過的指令裡搜尋（見「終端機頻道」）。
- `!help`: 列出機器人的指令。
- `!restart`: 重啟機器人。
- `!rollback`: 退回上一個正常版本。

## Claude Code 的指令和 skill
Claude Code 自己的 `/` 指令和 skill 也在選單裡，打 `/` 加幾個字就能搜尋。這些只能用 `/`，會送進 Claude。
- **Skill**：{{skill_examples}} 等。`args` 欄填要交給它的內容，例如 `/deep-research` 的研究主題。結果照常貼在頻道。
- **常用指令**：`/usage`（用量）、`/context`（context 佔用）、`/compact`（壓縮對話）、`/model`（`args` 填 `opus`、`sonnet` 之類就直接切換）、`/effort`、`/fast`、`/init`、`/security-review`。
- `/btw <問題>`：順便問一句。會開一個討論串回答，在討論串裡直接打字就是追問（前面的問答會一起帶上）。它看得到目前的對話，不會打斷正在跑的工作，問答也不會留在主對話裡。
- `/tour`：上手導覽，一步步帶你試主要功能。`args` 寫一項就只帶那一項（例如 `/tour 提醒`）。這個 skill 在引擎的 `skills/tour`。
- `/doctor` 是 Claude Code 自己的安裝檢查；Altention 的系統檢查（`altention doctor`）請跟 Claude 說「跑系統檢查」。
- `/cc`：執行選單裡沒有的任何 Claude Code 指令，`command` 欄可以打字搜尋。
- `/commands`：列出全部；裝了新的 skill 之後用 `/commands refresh:True` 更新選單（平常每天自動更新一次）。
- 不要某個 skill：把它所屬的插件在這台關掉（`disabled_on`）。只刪 `~/.claude/skills` 裡的連結，同步會在 15 分鐘內補回來。
- 會開面板的指令（例如 `/usage`、不帶參數的 `/model`）送出後會貼回畫面，並依面板最下面那行提示（例如「Enter to set as default · s to use this session only · Esc to cancel」）附上按鈕，按鈕只送提示上寫的鍵；看不出提示時用 `/key` 操作。面板會在你發下一則訊息時自動關掉。
- 也可以照舊把指令當成一般訊息打出來送出，效果相同。

## 接上你自己開的對話
你在 {{bot_machine}} 的 tmux 裡自己開的 Claude Code，可以原地接到一個頻道，不用重開。
- `/attach`：在任何頻道下都可以，不用自己先開頻道，也不用填參數。它會列出這台機器 tmux 裡正在跑的 Claude Code，每個對話下面有一顆按鈕；點一下，機器人就在「專案名稱」的分類下開好頻道並接上（專案名稱取自 git repo 或資料夾的名字）。例外：在一個剛開、還沒設定的頻道裡用 `/attach`，就直接接在這個頻道，不另開。
- 一次接上整個專案：清單裡有「📁 整個專案 …」的按鈕（同一個專案有兩個以上還沒接的對話時才會出現），不管它們開在哪個 tmux 裡都會一起接上。
- 頻道名稱是「tmux 名稱-視窗」，同一個 tmux 的視窗會排在一起；視窗有自己取名字就用名字，否則用編號。
- 接上時，機器人會把那個對話之前的完整內容貼進頻道（每一輪你打的話和 Claude 的最後回覆，不截短、不發通知）。長的對話有上百則，大約一秒貼一則，貼完有結尾標記；這段期間頻道照常可以用。
- 清單上的按鈕 15 分鐘後失效，點過一次也會消失，放著不管不會有事。
- 接上之後兩邊同時可用：在頻道打字會送進那個對話；你在終端機打的內容和 Claude 的回覆，頻道裡也看得到。
- Claude 用按鈕問問題時，題目會出現在頻道而不是終端機。
- `/detach`：在那個頻道裡下，意思是「Discord 不再跟著這個對話」，不會關掉任何東西（設定卡開的視窗也一樣，之後它就只是你 tmux 裡的一個普通視窗）。對話本身完全不受影響，繼續在你的 tmux 裡跑；頻道移到「封存」分類（主題最前面註明原本的分類，接回時搬回那裡），機器人不再處理裡面的訊息。在封存的頻道裡打字，會出現兩顆按鈕：「接回原本的對話」（原本的視窗不在了，會在同一個 tmux session 開新視窗接回；已經接在別的頻道時會先問你要不要移過來）和「在這裡開新對話」（跳設定卡）；打的那則訊息不會送給 Claude，接回或開新對話後請再送一次。之後對同一個 tmux 視窗再 `/attach`，也會把封存的頻道搬回來沿用，歷史訊息都在。同一個對話同時只會接在一個頻道。
- Claude 在終端機那邊結束時頻道會通知；在同一個 tmux 窗格重新開 Claude，會自動接回同一個頻道。窗格本身就是 Claude（外面沒有 shell）、或整個窗格被重開（respawn-pane）時，要接著原本那個對話（`claude --resume <id>`、`claude -c`）才會自動接回；在那種窗格開的是新對話，頻道不會跟過去，要 `/detach` 再 `/attach`。Claude Code 以外的 agent（pi、Codex 的轉接層）沒有 Claude Code 的對話紀錄：轉接層有照下面的規格在窗格留標記的話，機器人照頻道標籤和這個標記接回，並在頻道貼一行小字「這個頻道的窗格重開過，已經接回同一個窗格」；你在那裡換了別的 agent 的話，看到這行就知道要 `/detach`。沒有留標記的，照舊算窗格不見了。
- 轉接層（給寫轉接層的人）：要在 respawn-pane 之後讓機器人認得同一個窗格，轉接層啟動時在自己的窗格設 tmux 選項 `@altention_agent`，值是 `<agent 名>|<轉接層自己的 pid>`；有自己的對話 id 的話，再設 `@altention_session`。這個 pid 必須是轉接層程序本身：腳本用 `$$` 的話要接著 `exec` 轉接層（例如 `tmux set-option -p -t "$TMUX_PANE" @altention_agent "codex|$$"; exec codex-adapter …`），程式自己設的話寫自己的 pid；不要在互動的 shell 裡手動設。轉接層結束時用 `tmux set-option -p -u -t "$TMUX_PANE" @altention_agent` 清掉（`@altention_session` 也一樣）。標記指到 shell（bash、zsh、sh、dash、fish）的不算數，窗格前景的程式是 shell 時也不算，免得轉接層結束後機器人把訊息打進 shell：所以轉接層的主程式不能是 shell 腳本（tmux 會把它叫成 bash），要 exec 成 node、python 這類程式，也不要在窗格的前景跑 shell。機器人只在這個 pid 是窗格現在的程序（`#{pane_pid}`）或它底下的程序時才算數，所以重開前留下的舊值不會被誤認，不用清掉；有 `@altention_session` 時，它要跟頻道記的對話一樣才接回。機器人在窗格上寫的 `@altention_channel` 不要動。要知道自己是哪個頻道，用 `altention dc read --map`（別台也一樣）。
- **機器重開之後**：機器人開的視窗，下一則訊息會自己接回。接上去的對話，窗格已經不在了，要自己開回來：在 tmux 開一個視窗，到同一個資料夾跑 `claude --resume <對話 id>`（頻道裡的通知有寫），再用 `/attach` 選它。同一個對話，或同一個 tmux 視窗和資料夾，會接回原本的頻道，不會多開一個（在那裡開的是新對話也一樣，頻道會說怎麼換回原本的）；原本的窗格還在跑，或問不到那台機器，才開新頻道。當時在跑的那一輪和背景工作不會自己接著做，要你再說一次。
- 刪掉頻道不會關掉 Claude：它照樣在 tmux 裡跑，`#audit` 會記下它在哪裡，要關請自己關，或用 `/attach` 接到新頻道。機器人開的視窗被你在電腦上關掉的話，下一則訊息會在同一個 tmux session 重開並接回對話。
- 條件：那個 Claude 必須是在 tmux 裡開的。直接開在終端機裡的對話接不上，要先在 tmux 裡用 `claude --resume` 重開。
- 接上的頻道不能用 `/reset`、`/resume`、`/cwd`、`/mode`，那是你自己的終端機，機器人不會關它；要清空對話直接發 `/clear`。
- **對話之間互相討論**：在訊息裡用頻道提及（打 `#` 選頻道），例如在 {{example_channel_b}} 說「先看看專案，再把問題報告給 {{example_channel_a}}」。Claude 會用 `altention dc post` 貼過去，那裡的 Claude 會收到；來往在兩個頻道都看得到。
- **「打開」按鈕（插件的 Activity 頁）**：有插件提供 Discord Activity 頁面時（例如看檔案），Claude 可以用 `altention dc post <頻道> --activity <插件>/<頁>` 貼一則帶「打開」按鈕的訊息，按下去就在 Discord 裡開那一頁。大多數頁只有你按得動，別人按會看到「這一頁只有擁有者能打開」；插件標明不含私人資料的頁，伺服器裡的人都能開。Activity 要先照插件的安裝步驟設好，沒設好時按鈕會告訴你。
- **檔案的打開按鈕**：有插件的頁面能開檔案時（例如可以看檔案的頁面），Claude 用 `altention dc post --file` 貼的每個檔案下面都會有一顆打開按鈕，按下去就在 Discord 裡打開那台機器上的那個檔案（按鈕上的字由插件決定，一則有好幾個檔案時會接上檔名）。一則訊息最多 5 顆：檔案多、或好幾個頁面都能開檔案時，排在後面的檔案沒有按鈕；路徑特別長的檔案也沒有。插件確定沒設好時不附按鈕。
- **「填入」按鈕（插件要的金鑰）**：插件要一個金鑰或 token 時，Claude 不會叫你貼進對話，而是用 `altention dc post <頻道> --secret <插件>/<名字>` 貼一顆「填入 …」按鈕。只有你按得動（別人按會看到「只有擁有者能填這個。」）；按下去跳出輸入框，貼上後按送出，值就存在機器人那台（Claude 要讀會被擋下，跟機器人的 token 一樣），只有你看得到的回覆說「存好了」或「沒有存：原因」，#audit 記一行（只有插件和金鑰的名字）。值會經過 Discord，**輸入時看得到字**（Discord 的輸入框不會遮）；不想經過 Discord，就在機器人那台的終端機跑 `altention secret set <插件> <名字>`。存好之後按鈕會變成「✅ 已填入 …（再按可以換）」，再按一次就換成新的值；輸入框最多 4000 字，更長的請用終端機。按鈕 7 天後失效。這個插件還有別台在用時，「存好了」下面會多一行，列出是哪幾台；要放過去，到 #setup 跟 Claude 說「把 <插件> 的 <名字> 也放到 <機器>」，它問過你才送，而且只送到你說的那台。
- `/rename <名字>`：頻道名、Claude Code 的對話名、tmux 的 window 名一起改；session 是機器人替這個頻道開的，也一起改（尾巴的編號留著）。回覆逐項寫 ✅ 改了、❌ 沒改成（附原因，例如 Discord 限制 10 分鐘只能改兩次頻道名）、➖ 這個頻道不適用。在 Discord 手動改頻道名，或在 tmux 用 rename-window 改 window 名，其他的也會照樣跟著變（tmux 依程式自動取的名字不算）。別的頻道的 Claude 也能改：`altention dc post <頻道> --rename <名字> --why "…"`，卡片和 #audit 會寫是哪個頻道的 Claude 改的。
{{#attach_machines}}- **別台機器**：`/attach` 也會列出 {{attach_machines}} 上 tmux 裡的 Claude（會標出機器名稱），接上之後用起來一樣。之後要加別台，在機器清單給它 `dcattach` 角色就行（那台要能從 {{bot_machine}} 用 SSH 連到）。別台的 Claude 用 `altention dc post <分類>/<頻道> --new-claude <資料夾>` 開新頻道時，頻道會開在它自己那台你的 tmux，跟在設定卡選那台一樣。用 `--on` 開在別台時，`~` 要加引號（`'~/…'`），不然這台的 shell 會先換成這台的家目錄。別台機器的對話目前還不支援 📋 看過程。{{/attach_machines}}{{^attach_machines}}- **別台機器**：別台機器 tmux 裡的 Claude 也能接上。在機器清單加上那台並給它 `dcattach` 角色（那台要能從 {{bot_machine}} 用 SSH 連到），`/attach` 就會列出它。別台的 Claude 用 `altention dc post <分類>/<頻道> --new-claude <資料夾>` 開新頻道時，頻道會開在它自己那台你的 tmux，跟在設定卡選那台一樣。用 `--on` 開在別台時，`~` 要加引號（`'~/…'`），不然這台的 shell 會先換成這台的家目錄。別台機器的對話目前還不支援 📋 看過程。{{/attach_machines}}

## 終端機頻道
設定卡選 💻 的頻道是一個真的 shell（你的 zsh 和設定都在），開在你的 tmux 裡。
- 每則訊息就是一行指令（多行就是依序執行多個指令）。輸出貼成一個程式碼區塊，跑的時候每幾秒更新，結束時標示結束碼；輸出很長時另外附完整的檔案。
- 每則輸出下面有 Ctrl-C、🔁 再跑一次、📺 畫面。
- 指令還在跑時再發的訊息，會當成輸入打給它（例如回答 y/n、輸入密碼）。
- `/run`：在指令欄打幾個字，會列出這個頻道跑過、符合的指令可以直接點。shell 自己的 `!!`、`history` 也照樣能用。
- `/stop` 送 Ctrl-C；`/screen` 看整個畫面；`/reset` 關掉這個 shell，下次打指令會開一個新的。
- 打什麼就跑什麼，沒有確認。`vim`、`htop` 這類全螢幕程式不適合在這裡用。

## 看檔案
- `/files`（或 `!files [路徑]`）：在任何頻道叫出檔案瀏覽器，從這個頻道的資料夾開始，在這個頻道所在的機器上{{#example_machine}}（{{example_machine}} 頻道就看 {{example_machine}} 的檔案）{{/example_machine}}。只有一則訊息，點了原地更新，看完按 ✖ 關掉。
- **資料夾**：清單在程式碼區塊裡（資料夾在前，附大小或項目數，`M`／`?` 是 git 改過／新檔），下拉選單點一下就進資料夾或打開檔案。一頁 25 項，多的用 ◀ ▶ 換頁，或按 🔍 打檔名的幾個字找（例如 `tmux br`，會找整個資料夾底下）。⬆ 上層、🏠 回起點、👁 顯示隱藏檔。
- **檔案**：一頁幾十行，有行號、依副檔名上色；◀ ▶ 翻頁、↧ 跳到第幾行、📎 把整個檔案當附件傳（手機可以直接開）。圖片直接顯示；Markdown 可以切成 📖 排版後的樣子。
- **Claude 提到的檔案**：Claude 的回覆裡提到的檔案（例如 `bot/setup.py:142`），回覆下面會有 📂 按鈕，點了直接打開到那一行。
- **📂 檔案頻道**：設定卡選 📂，選機器和資料夾（點選或打路徑），這個頻道就是那個資料夾的瀏覽器，一直都在。直接打字就是找檔案；打路徑（可以加 `:行號`）就跳過去。瀏覽器會移到最下面。
- 只能看不能改，要改請叫 Claude。放金鑰和 token 的地方（`~/.config`、`~/.ssh`、`.env`、金鑰檔等）不會顯示，連檔名都不會出現。

## 插件

有些功能是插件，要不要開由你決定。

- **看有哪些**：問任何頻道的 Claude「有哪些插件可以裝」。官方插件是 altention 組織在 GitHub 上公開、名字是 `plugin-<名稱>`、有發佈版本的 repo；每台機器一天看一次這份清單。新安裝時，#setup 也可能直接問你要不要開某個官方插件。
- **裝官方插件**：到 #setup 跟 Claude 說「裝 <名稱>」。它會先說這個插件會在你的電腦上做什麼、用在哪幾台，你答應了才裝。會看到對話內容的插件會另外再問一次。還有事要你做的（裝工具、填金鑰、到別的網站設定），它會一步一步帶你；中途停下，回來說「接著裝 <名稱>」就從還沒好的那一步接著。
- **別台機器**：裝完它會問要不要現在也裝到別台。先不裝的話，別台下一輪更新會拿到插件的資料夾，但排程和 hook 要等那台套用設定才有；之後在 #setup 說「幫我把 <名稱> 裝到 <機器>」就好。
- **關掉、打開**：跟任何頻道的 Claude 說「關掉 <名稱>」。它會先說會少掉什麼（包括要靠它的其他插件），你答應了才關；說「打開 <名稱>」就回來。可以只關某一台。
- **更新**：插件有新版本時，#update 的卡片會寫。多要了東西的版本（例如新的排程、hook）不會直接更新，會請你到 #setup 看過再決定。
- 插件跟 Claude 一樣跑在你的電腦上，沒有隔離，只裝你信任的。

## 出狀況時
1. **沒反應，或出現「⚠️ 訊息可能沒有送進 Claude」**：先 `/screen` 看畫面。卡在面板或選單就 `/key Escape`，再重發訊息。
2. **跑太久或方向錯了**：`/stop`，然後直接說要怎麼改。
3. **對話整個亂掉**：`/reset` 開新的；想回去用 `/resume`。
4. **tmux 模式本身有問題**：`!mode print` 切到備用模式，對話會接續。機器人這台的頻道被改成簡易模式（沒有選單和按鈕）或純文字模式（看不到它做到哪）時，回覆最後會標出來，第一次也會列出暫時沒有的功能；這是機器人自己判斷的：Claude Code 新版的畫面認不得、而且在乾淨的地方試兩次都一樣，才會改。Claude Code 換了版本、檢查通過，會自己回到一般模式；也可以用 `!mode retry` 當場再試一次（下一則訊息會重新開 Claude Code，接續原本的對話）。這段期間同時最多處理 3 則，其他的排隊，頻道會說前面還有幾則。Claude Code 新版的畫面壞了時，如果之前用 `!cctest` 檢查通過過某一版（機器人會留一份），機器人會先退回那一版繼續用一般模式；停在舊版超過 7 天（`dcbot.cc_pin_days`）會問你要繼續停還是改用新版的簡易模式。`!cctest` 用真的 Claude Code 檢查目前的版本（大約 5 次 Haiku 對話），通過就留一份當退路。Claude Code 每次更新後，機器人會自己用假的 API 演練一次（不用登入、不花用量），結果記在 #audit。你自己用 `/attach` 接上的窗格不會被改：機器人認不得它的畫面時會在頻道說，你可以直接在終端機用，或關掉那個窗格後用 `!mode print` 在這裡接著原本的對話。
5. **「⚠️ 這個頻道的窗格不見了」**：機器人每 2 分鐘看一次每個頻道的 Claude Code 窗格還在不在。確定不在了（那台連得上、tmux 說沒有那個窗格或 server）才會在頻道說一次，窗格回來時再說一次；那台連不上時只當作不知道，不會說。接上的窗格：在那台把 Claude Code 開起來（`claude --resume` 接同一個對話）再 `/attach`；機器人在你 tmux 開的視窗：下一則訊息會在原本的地方重開。用 `/where` 看這個頻道現在在哪裡。
6. **新版本壞掉**：新版本 3 分鐘內沒上線會自動退回上一版；也可以手動 `!rollback`。
7. **想自己接手**：SSH 到 {{bot_machine}} 執行 `tmux -L dcbot attach -t <名稱>`，名稱看 `/status`。
8. **機器人的權限**：機器人上線時會看自己的權限，記在 #audit，之後權限有變也會記（Discord 的審核日誌不記這件事）。沒有「管理員」權限時，#update 會貼一張卡（只貼一次），系統檢查（doctor）也會一直列著。為什麼要：之後的功能需要它，例如把伺服器設成社群伺服器、設定規則和公告頻道；不給也照常能用，現在的功能都只用原本的 14 項權限。要給：打開卡片上的連結，畫面會寫「新增至伺服器」，照按「授權」，不是重裝，機器人不會被踢掉；或在伺服器設定 → 身分組 → 機器人的身分組打開「管理者」（Discord 畫面上管理員權限叫這個名字）。之後想收回：doctor 會列一個連結，用它再授權一次只會回到原本的 14 項；或在身分組關掉「管理者」。機器人不能自己拿權限，一定要你操作一次。

## 備援（機器人那台停了時）
- **怎麼設**：在 #setup 說「設備援」，選另一台、選「自動接手」或「只通知」；或在機器人那台跑 `altention standby setup <機器> auto`（或 `notify`）。「自動接手」會把機器人的 token 多放一份在那台（放在那台的祕密資料夾）。
- **停了會怎樣**：機器人那台停了約 5 分鐘，備援接手，通知頻道 @ 你一次，說哪幾個頻道能用。原本那台上的頻道經 ssh 接著用；那台整台不見時，那些頻道會說連不上。接手期間提醒和用量看板暫停；狀態看板改由備援那台接著貼。
- **看板上看得到**：「機器和機器人」看板寫現在哪台在當機器人、備援在不在。
- **切回**：原本那台回來、連續 30 分鐘都正常，就自動切回（通知頻道說一行，不 @）。想自己決定什麼時候切回：設 `dcbot.failback: ask`，會出現「切回」按鈕。
- **外部通知**：在 #setup 說「設外部通知」，照著在 healthchecks.io 建一個免費的檢查、把網址貼進機器人給的框（Claude 看不到）。當下是機器人的那台定時回報，兩台都停了 healthchecks.io 會通知你。
- **限制**：
  - 接手後 30 分鐘內不會再接手。
  - 24 小時內換到第 3 次，就停在當下那台，不再自動切換，原本那台回來也不會自己切回；那次的接手通知會講，要人去看原本那台怎麼了。
  - 兩台的引擎要一樣新，差太多時只通知、不接手（doctor 會說）。
- **暫停**：在備援那台的 `~/altention/engine/dcbot/state/` 放一個叫 `stop` 的空檔，那台就不會接手（刪掉就恢復，最多等 5 分鐘）。備援正在當機器人時，要等它切回之後才生效。
- **拿掉**：目前沒有一句話就拿掉的指令，請 Claude 照這幾步做：從機器清單拿掉那台的 `dcbot-standby` 角色、對那台跑 `python3 ops/apply.py <機器>`、照 doctor 說的在各台清掉留下的紀錄（`lease.owner-left`），最後重啟機器人。
- **只通知模式**：選「只通知」時：不放 token，那台只會在機器人停了、或連不上 Discord 太久時，用 webhook 通知你。

## 已知限制
- 補充訊息要等 Claude 手上那個工具跑完才會被看到；急的話加 `!!` 立刻送出。
- `/btw` 的各個討論串大致是分開的，但 Claude Code 會記得「上一個 btw 問題」，所以剛換到另一個討論串的第一題，偶爾還會參考到前一個討論串的最後一題。
- Claude 用按鈕問問題時會一直等你回答（最多 12 小時）。只剩一題時，打字就是回答；還有好幾題沒答時，打的字要等全部答完才會被看到。不想答就 `/stop`。計畫核准只能用按鈕。
- `/reset`、`/cwd`、`/resume` 切換對話、`/mode` 切換模式，都會結束該對話裡的背景工作。
- 機器重開後 tmux 對話會消失：機器人會在頻道通知，下一則訊息自動接回對話，但當時在跑的工作和背景工作會中斷。要長期跑的服務請 Claude 做成 systemd 服務。
- 多個頻道用同一個工作目錄時，同時改檔案或 commit 會互相衝突。
- Claude 貼回自己頻道的一般訊息，轉發給別的頻道時只看得出是「機器人的訊息」，分不出是哪個 Claude 的回覆。
- 「照送出的順序」只對同一種寫法的頻道成立：同一個 Claude 一次用頻道名字、一次用頻道 ID 貼到同一個頻道，兩邊各排各的，順序可能交錯。
- 對話開在別台機器的頻道：`/resume` 的選單不會列出可選的對話（Discord 要馬上回應，來不及問那台）；請用 `!resume` 看編號清單，再 `!resume <編號或 id 開頭>` 接回。
- 別台機器上的對話，機器人是用 ssh 進去讀那台預設位置（`~/.claude`）的對話檔。那台的 Claude Code 若用了自訂的 `CLAUDE_CONFIG_DIR`，📋（展開一輪）和 `/resume` 之後貼的對話紀錄會讀不到，頻道會說那台不給讀；回覆本身不受影響。
- 終端機裡輸入框空的時候按「←」會進到 Claude Code 的背景對話清單，原本的對話搬到背景繼續跑，頻道照樣收得到它的回覆；按 Esc 就回到原本的對話。清單畫面上機器人不會替你打字（接上的窗格請你自己按 Esc；機器人開的對話它會先按一次 Esc）。限制：在清單裡直接打字會開一個**全新的背景對話，沒有任何頻道跟著它**；窗格正在看那種對話、而畫面最上面的標頭已經捲走時，從 Discord 發的訊息會進到它而不是這個頻道的對話（等不到回覆時機器人會提醒你到終端機確認）。`/bg` 把對話整個丟到背景後，頻道也跟不到那一份：下一則訊息接回的是原本的對話。對話搬到背景之後把視窗或窗格關掉，那個對話還會留在 Claude Code 的背景裡；頻道的下一則訊息接不回它、會開新的對話，要找回它請在終端機用 `claude attach <對話 id>`。
- `/attach` 或 `/resume` 貼對話紀錄的那段期間照常可以打字；這時到的即時訊息和回覆會出現在「以下是…」和「以上是…」兩個標記之間，內容不會少。
- 對話搬到背景又回來後，窗格窄於約 80 欄時可能被誤判成不在忙：回覆照樣會貼，但這段期間 `!stop` 會說沒有正在跑的工作、停不了那一輪。有背景 shell 時狀態列較短，約 70 欄以上不受影響。沒搬過背景的對話，窄於約 70 欄時也可能讀不到在忙（60 欄量過）。
- 閒置 12 小時、沒有背景工作的對話會被關掉省資源，下一則訊息自動接回。
- Claude 執行指令不會逐次問你同意。刪頻道、刪檔、強制推送這類動作，它會先在對話裡問。
- 同一個帳號的 Claude 之間沒有隔離：同一個帳號裡的 Claude 對話都跑在同一個使用者的 tmux 裡，任何一個都能用 shell 對別的對話送按鍵，包括按掉權限選單。所以權限選單和 Discord 的核准按鈕是用來防誤操作，不是 agent 之間的安全隔離；機器人只給你、不給 agent 用的指令也一樣，只是沒有官方的路，不是擋得住。要真的隔離，就把不信任的工作放在別的帳號、別的機器，或沙箱裡跑，這不在 Altention 的範圍內。預設權限模式（`dcbot.default_permission`）三種各是什麼，見 SECURITY.md 開頭（就是 #setup「權限」那一題的三個選項）；一個頻道設 `manual`，別的頻道是 `bypassPermissions` 時，它一樣會被按掉。
- 附件上限 100 MB，存在 {{bot_machine}} 上，14 天後自動刪除。頻道的 Claude 在別台時，25 MB 以內的附件也會送到那台（同樣 14 天後刪除）；更大的或送不過去的，Claude 會知道檔案在哪台和原本的網址。
- 輸入框裡有字、訊息送不出去時，提示的 `/key C-u` 只清得掉游標所在那一行，多行或游標不在行尾時清不完。先用 `/screen` 看：Claude 沒在跑時，`/key C-c` 按一次就能全部清掉，但不要連按（一秒內按兩次會關掉 Claude）；Claude 正在跑時按 `C-c` 會中斷那一輪。

## 秘密和遮蔽
- 機器人的 token 和 SSH 私鑰（公開金鑰、`~/.ssh/config`、`known_hosts`、`authorized_keys` 不算），以及你在實例 `plugins.json` 的 `core.secret_paths` 加的路徑，不會被任何 Claude 讀到：每台機器的每個 Claude（包括你自己開、再 `/attach` 的）要讀、改、搜尋這些檔（或搜尋裝著它們的資料夾，例如 `~/.config`、`~/.ssh`），或下的指令裡寫了這些路徑（含 `$HOME`、`~`、萬用字元的寫法；就算只是要印出或貼出的文字），都會被擋下並說明原因。heredoc 內文和引號裡的萬用字元（例如程式註解的 `/**`）不算路徑；交給 `bash -c`、`ssh`、`eval` 執行的文字當指令看。`ssh -i`、`ssh-add`、`ssh-keygen -y` 這類使用鑰匙的指令放行。這是盡力而為的守門，不是隔離：擋不到 `cd` 之後用相對路徑、以整個家目錄為範圍的搜尋、執行時才拼出的路徑、另寫程式去開檔；token 檔另有 600 權限。要整個關掉，設 `core.secret_guard` 為 false。
- 貼到 Discord 的 Claude 文字和工具輸出裡，像金鑰、token、私鑰的字會換成 `[REDACTED]`，並加一行小字說遮了幾處（雜湊、ID 不遮）。`/screen` 和選單畫面是畫面本身，不在內。按 📝 看的圖的原文也一樣，存之前就遮了。
- 機器人的狀態檔裡有兩欄是對話內容：`state/waiting-on-owner.json` 每一項的 `text`（在等你回答的問題；選單和計畫是那個頻道的 Claude 最後說的話的第一句）、`state/channels.json` 每個頻道的 `doing`（在忙時 Claude 最近一段中途的話的第一句，一輪結束就拿掉）。都先遮金鑰，再截成一行、最多 80 字，沒有內容就不寫。這兩欄是對話內容的一行摘要，只存在機器人那台。檔案是機器人內部用的，插件不要直接讀；之後的版本會有給插件用的正式唯讀指令，到時候插件才可能把它顯示在別處（例如你手機上的頁面）。

## 改機器人說的話
- 訊息沒送出時機器人說的那些句子（「⚠️ 終端機現在不是一般的輸入框…」之類）可以換成你自己的說法：在實例的 `plugins.json` 加 `dcbot.text`，一句一個鍵，例如 `{"dcbot": {"text": {"not_sent.claude_code.dialog": "有對話框開著，這則沒送出。"}}}`。存檔後最多一分鐘生效，不用重啟。
- 鍵是「組.代號」。組有 `not_sent`（沒送出）、`unconfirmed`（送了但沒等到回音）、`notes`（順帶說的，例如「已經重送」）、`cleared`、`far`（那台機器連不上時說的）。全部的代號和預設的句子在 `dcbot/bot/messages.py`；原句裡的 `{text}`、`{screen}` 這類是會代進去的內容，照樣寫在你的句子裡就會出現。
- 寫錯不會壞：值不是文字的那一鍵不算；`plugins.json` 整個讀不到時用預設的句子。目前只有這一類句子能改，其他的之後才會搬過去。
