- `bot/pauses.py`（C-184）：`altention dc post <頻道> --pause-until <時間> --why`／`--unpause --why`。時間在 `altention/dc/pausetime.py` 解讀（實例的 `core.timezone`，最多 7 天），機器人收到 epoch。頻道狀態 `paused` `{by, by_ch, why, until, at, msg, card, held}`，在 `standby.MATTERS` 裡。暫停中：別的 Claude 的 post 照樣貼卡片（footer 寫恢復時交給 Claude），存進 `held`（最多 `MOST_HELD` 50），寄件方由回條或它的頻道得知；`--answer`、`--talk-continue` 拒絕；`--waiting`、使用者的訊息和按鈕不擋。`pump_round()` 的每分鐘檢查呼叫 `Pauses.chores()`（只比較，貼和交付走 `Posts.later()` 的獨立工作）：到時間 `resume()` 每一步做完才記（`resumed`：#audit 和 ⏸️ 卡片結尾「（已恢復）」；`shown`：▶️ 貼上 Discord，失敗 #audit 說一次、下一分鐘補貼；`told`：Claude 收下 ▶️ 那段，不確定就再交一次並標「（重送）」，至少一次，manager 2026-11-12），再照順序交 `held`，每則交完才拿掉（交不進去 #audit 只說第一次，下一分鐘接著交）；恢復到一半又被暫停時，新的暫停接走還沒交的（正在交的那則除外），收尾只在 `st["paused"] is p` 時拿掉；機器人停著時過了時間的，上線後第一輪補叫、寫晚了幾分鐘。**C-199**：使用者在暫停中的頻道說話、那則當成一般訊息打進去、按了 Enter 之後（`TmuxBridge.submit(typed=)` → `Bot.woken()`；「/」指令、等確認的 /exit 這類、/logout、/btw、沒送進去的都不算，manager 11-17；print／文字模式等恢復時再交），`wake()` 在獨立的工作裡把當時已留著的照順序交（`give_held()`，跟 resume 共用），交一則拿掉一則；之後來的照樣留，暫停不解除；交不進去的留在最前面，#audit 說一次，等恢復或下一次說話；`wake()` 進行中 `chores()` 跳過那個頻道，`resume()` 等它做完。`--drop-held --why`（`drop()`）：只有查證過、寄件頻道就是那個頻道（或它的討論串）的 Claude 能清，#audit 記清掉幾則。`dcctl paused`（`altention dc read --paused`）和看板「暫停中的頻道」讀同一個欄位。
- **「沒送出」是代號，字在 `bot/messages.py`**（3b 2.6a，backlog A-09）：送訊息前的檢查（`may_type`、`leave_list`、`resend`、`clear_leftover`、`enter`，和 `/btw` 的那幾種）**自己不說話**，回一個 `Typing`（真＝可以打；否則 `state`、`code`、`data`，另有 `notes`＝順帶要說的、不是失敗，例如「已經重送」），由 `told()` 查 `messages.not_sent(code, **data)`／`messages.note()` 貼出來；頻道最近一次的結果留在 `rt.outcome`（2.7 搬進接頭後就是 `send` 回的東西）。**代號兩層**：共通的少數幾個（`not_ready`、`busy_elsewhere`、`needs_owner`、`refused`、`unknown`）和接頭自己的（`claude_code.shell_mode`…），每個接頭的代號在表裡寫明屬於哪個共通代號、以及是暫時的（等一下重送可能就過）還是重送也沒用的（協定「已貼出，未交到 agent」要帶的兩樣）。**表裡沒有的代號**用一句通用的話（帶代號和資料）說，所以新接頭或 Claude Code 多一種對話框時 `bot/` 不用改。打完字之後才知道的（已按 Enter 但沒等到回條）在 `UNCONFIRMED`，不算沒送出。**取一句話只讀記憶體**（`messages.words()`；#code-review 在 3f8e783 量到經 `text.t()` 每句都讀 plugins.json，檔壞時在事件迴圈裡等 0.4 秒）：預設字在 import 時登記進 `altention.text.TEXT`（加語言就加在那張表）；這個安裝的語言（`core.language`）和它自己的說法（實例 plugins.json 的 `dcbot.text`：`{"<組>.<代號>": "…"}`，組是 `not_sent`／`unconfirmed`／`notes`／`cleared`）由 `messages.load()` 讀進記憶體，`load()` 只在執行緒裡跑（`TmuxBridge.read_words()`：啟動時等它一次，之後每分鐘由 `pump_once()` 起一個、不等；檔沒變就不重讀）。設定讀不到 → 用預設字、log 一行、不丟例外。`told()` 對同一個 `Typing` 可以叫很多次，`notes` 只說一次；`checked()`＝`may_type()`＋`told()`，檢查中途丟例外時已經記下的 notes（「已經重送」）照樣說。**新增一種沒送出的情況：在 `messages.py` 加一列，程式裡 `r.refuse("代號", 資料…)`，不要在原地寫句子。** 2.6a 只搬字不改字：`tests/samples/words/before-2.6.json` 是搬之前程式裡的每一句（用程式從原始碼取出），`test_messages` 守著逐字相同；之後真的要改字，連樣本一起改並在送審時寫明。`rt.typing` 是「正在輸入」那個工作，不是這個。
