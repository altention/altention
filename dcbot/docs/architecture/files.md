# 檔案和附件

從 `dcbot/CLAUDE.md` 的「架構」搬來，原文沒改（2026-11-19）。路徑相對於 `dcbot/`；接頭指 `altention/connectors/claude_code/`。

- `bot/files.py`、`bot/filecore.py`：檔案瀏覽器。一則訊息原地更新：資料夾是程式碼區塊加下拉選單（一頁 25 項，選單的上限），檔案是一頁有行號的程式碼區塊（依 `BUDGET` 字數切），圖片當附件顯示。讀檔一律走 `filecore.op()`（只用標準函式庫）：本機直接呼叫，別台機器走 `dcremote files`（JSON 進出）。`filecore.blocked()` 擋掉放秘密的地方（`~/.config` 整個、`~/.ssh`、金鑰、`.env`、history…，以及 `/proc`、`/sys`、`/dev` 整棵：同一個使用者每個行程的環境變數和指令列都在 `/proc` 裡，2026-10-21 一次審查量到 `raw('/proc/self/environ')` 整份送出），用解析後的真實路徑判斷，連結繞不過去，清單和搜尋也不會出現它們的名字；讀檔一律經 `open_regular()`：只開一般檔案（`O_NONBLOCK`、`O_NOFOLLOW`、`fstat` 是 `S_ISREG`；FIFO、裝置、socket 不開），Linux 上開好之後再用 `/proc/self/fd` 對開到的那個檔問一次 `blocked()`；**不要放寬**。每個瀏覽器的狀態在頻道狀態 `browsers`（訊息 id → 狀態），按鈕 `fb:<動作>` 靠訊息 id 找狀態，所以重啟後照樣能按。三種模式：`temp`（`/files`、`!files`，✖ 關掉）、`channel`（📂 檔案頻道，`kind: "files"`、`st["files"] = {host, root, browser}`；`main.on_message` 把打的字交給 `Files.typed()`：路徑就跳過去，其他就搜尋，瀏覽器重貼到最下面）、`pick`（設定卡的 📁：卡片本身變成只列資料夾的瀏覽器，✅／← 交回 `Setup.picked()`；選好的資料夾記在 `Setup.folder`，當作後面各選項的工作目錄）。Claude 每則正式回覆送出後，`Files.add_links()` 在背景找出裡面提到、而且真的存在的檔案（`mentioned()`），在那則訊息加最多 5 顆 📂 按鈕（`fbl:<i>`，對應存在 `st["links"]`）。
- `bot/attachments.py`：使用者傳的附件先存到 `state/attachments/<頻道>/`，把本機路徑交給 Claude（Discord 的附件網址會過期，Claude 也沒辦法直接看網址上的圖）。14 天後自動清掉。頻道的 Claude 在別台（`files.host_of`）時，再用 `dcremote attach` 送一份到那台的 `state/attachments/<頻道>/`，給 Claude 那台的路徑（C-107）：25 MB 以內，限時 60 秒，只送一次；太大或送不到就給這台的路徑和網址，訊息照常送進去。遠端那邊只靠 `bot/attachcore.py`（不能載入 config.py），只收純數字的 id 和已經過 `safe_name()` 的檔名，寫入路徑一定在它的附件資料夾底下，並且在那邊清掉舊檔。檔名用使用者原本的名字（`name_of()`）：不是純 ASCII 的檔名，Discord 會在 `filename` 換成一串亂碼，原名放在 `title`（沒有副檔名時補上 `filename` 的）。`safe_name()` 保留各種語言的字，最多 80 個字元、UTF-8 150 bytes（前面加兩個 id 仍在檔名上限 255 bytes 內），切的時候保留副檔名；舊引擎的 dcremote 也收這樣的名字。那台拒收（結束碼 2，沒寫任何東西）時，改用 `filename` 再送一次；不知道有沒有送到的不重送。**開 Claude 時交出附件資料夾（C-151）**：機器人開的每個對話（自己的 tmux、設定卡的視窗、別台的視窗、print 模式）都把 `<那台的 state/attachments/<頻道>>` 放進 settings 的 `permissions.additionalDirectories`（本機：機器人設定檔的副本 `state/claude-settings.<12 碼>.json`，`cc_launch.with_folders()`；別台：`--settings` 只帶這個的 JSON；print：`claude_bridge.settings(dirs)`。不用 `--add-dir`：Claude Code 2.1.326 起對 `--add-dir` 的資料夾會問信不信任，頻道停在那個畫面開不起來，11-17 v0.6.0／v0.5.5），讀附件不跳「Read outside the working directories」或權限問題。全部經過 `TmuxBridge.argv(..., dirs)`（`dirs` 是必填，新的開法不能漏）和 `attachments.folders(host, 頻道)`：本機 `attachcore.folder()` 先建好（Claude Code 啟動時不存在的資料夾會被默默丟掉，之後建也沒用；2.1.316 實測），別台用 `dcremote attachdir` 在那台建、回那台引擎的路徑；建不成就照開、不帶，寫一行 log。路徑不解開連結（交出連結路徑，經連結和經真實路徑讀都算在裡面；反過來不行）。`/attach` 接上的窗格不是機器人開的，不處理。只交出這個頻道自己的資料夾。
