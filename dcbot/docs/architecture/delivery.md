從 `dcbot/CLAUDE.md` 的「架構」搬來，原文沒改（2026-11-19）。路徑相對於 `dcbot/`；接頭指 `altention/connectors/claude_code/`。

- **讀回訊息和 ledger**（C-172a P1a，規格在實例 `docs/refactor/c172a-design.md`）：讀頻道訊息的地方（`dcctl history`／`altention dc read`、回覆的上下文、轉發、只傳貼圖或投票時交給 Claude 的字）都經過 `bot/msgtext.py` 的 `text_of()`（Discord REST 形狀的 dict；`of_discord()` 把 discord.py 的 Message 轉成它）：整棵元件樹照畫面由上到下排，embed 讀 author／title／description／fields／footer，V2 的 Container 每行前面加「▌」、有顏色寫「〔黃〕」，Section 旁邊的按鈕或縮圖、按鈕列、選單、圖、檔案都寫成〔…〕；附件照舊由呼叫的人列網址。`bot/ledger.py`：機器人發的每則訊息記在 `state/ledger.json`（`{"channels": {頻道: [[訊息 id, {from, as, intent, key, framed, at}], …]}}`；intent 是 talk／post／notify／board／card／reply／status，framed 是機器人加的框：card、notice_head、board_head、status、interim），每頻道 `PER_CHANNEL` 500、總共 `TOTAL` 兩萬，記一筆後 `SAVE_SECS` 1 秒在 timer 執行緒裡轉成文字、交給 statewrite 寫（不在事件迴圈 dumps）；在 `standby.SYNCED`；頻道刪了就 `forget_channel()`。現在記的地方：最後回覆（最後一則有狀態行才標 status）、中途的話、posts 的卡片／貼回自己頻道／通知／看板（寄件人是 handle 查到的，`posts.sender_said()`）、提問卡、計畫卡、選單卡；其餘（P1b 的 `deliver()` 收齊之前）還是讀的時候猜。`frames.of(…, entry=)`：有 ledger 就照它分種類、只拿掉它記著的框（回覆裡 Claude 自己寫的「-# ×3 · 10 秒」小字不會被當成狀態行切掉；看板後面幾則也照 key 認），問過 ledger 卻沒有的才照字首猜、標 `guessed`（「未登記」），沒問過的（`NOT_LOOKED`）照舊。看板（`status/boards.py says()`）讀回比對時，ledger 記著是看板的那則不靠第一行 📌 認。測試一律用 `DCBOT_LEDGER`（`tests/tmuxguard.py` 指到每次自己的暫存資料夾），不碰正在跑的機器人的 ledger。
- **單一出口 `bot/deliver.py`**（C-172a P1b，分四批搬，manager 11-16：每批嚴格、上線觀察後才送下一批）：機器人自己的訊息一律 `deliver.deliver(to, *args, intent=, edit=, frm=, key=, framed=, **kw)` 送或改（參數原樣交給 discord.py 的 `send()`／`edit()`，不加不改）、`deliver.remove(to, 訊息或 id)` 刪，ledger 在這裡記。第 1 批已搬：posts.py 的全部（傳話卡、貼回自己頻道、通知、#audit 備援、看板送改刪、⏸️ 那行和它的 ✅、來回上限的卡和改字、▶️、`--new-claude` 的兩句和設定卡的 ✅、沒交到的那句）、tmux_bridge 的 `say()`（大部分通知都經過它）、最後回覆（含圖）、整理排版中、中途的話、處理中（送、改、刪）。第 2 批：提問卡、計畫卡（含計畫本文）、打字沒被收下那句、取消時改卡（ask.py 用 `from . import deliver as outgoing`：它自己有一個交答案給 hook 的 `deliver()`）、選單送／改（重新接上、按了、畫面變了、面板）、@ 那行和它的 ✅、整台卡住的 @、它的清單改字、恢復了（calls）、沒送出的提示和再送一次（unsent）、用量上限的各句（quota）、暫停的卡和恢復（pauses）、代答改卡和停在舊版提醒（agentanswer）。第 3 批：其餘全部（main、archive、process 和較小的模組；main 的指令回覆經 `Bot.answer_in(ch)`），`tests/test_one_way_out.py` 釘住 bot/ 裡除了 deliver() 沒有別的地方送、改、刪頻道裡的訊息（interaction 的 response／followup 不算），例外列在它的 FILES／CALLS，每項寫原因（lease.py、layout.py、改頻道或討論串本身的 edit）。不需要記帳的帶 `keep=False`：很快刪掉的暫時訊息（處理中、整理排版中、📋 的提示）、機器人自己的紀錄（#audit）、子代理／workflow 討論串裡的紀錄（任務、工具行、結果；頻道裡那行狀態照記，P1c manager 11-16）、接上時補貼的對話（一次幾百則會把卡片和看板擠出每頻道 500 筆）。改訊息時沒說的 `frm`、`as_`、`key`、`framed`（預設 None）沿用 ledger 原本那筆（只改按鈕的 edit，例如回覆加 📂、選單關按鈕），真的要清掉 framed 就明寫 `framed=()`；`remove()` 刪了（或 Discord 說已經不在：NotFound，照樣往上丟）就 `ledger.forget()`。頻道本身的 `ch.edit(category=/topic=)` 不是訊息，不搬。**每一批送給 Discord 的內容要跟搬之前逐欄位相同**：`tests/payloadlog.py` 用會記錄的假頻道跑各種情境，基準 `tests/samples/payloads/<批>.json` 在那批搬之前的 commit 錄，`tests/test_payloads_same.py` 比對；新增情境要在搬之前錄。
- **工具進來的訊息的規則 `bot/rules.py`**（C-172a P1c，manager 11-16）：純函式、只用標準庫（dcctl 也用），dcctl 送進佇列前查一次、機器人 `posts.from_dcctl()` 再查一次（佇列是檔案）。@：`ping`（dcctl send-json 的 `--mention owner|user:ID|role:ID`）owner 一律可以，user／role 要實例 `dcbot.json_mentions: "any"`（`messages.load()` 讀進 `loaded["json_mentions"]`，不在事件迴圈讀檔），@everyone／@here 拒；內容（content、V2 Text Display）寫了 @everyone／@here 也拒；`--mention owner`／`dcctl send --mentions` 只有內容（content、V2 Text Display）真的寫了擁有者的 `<@ID>` 才多記一行 #audit（`rules.owner_pinged()`；只允許、沒用到的不記，manager 11-17）。按鈕：custom_id 都要 `user:` 開頭（連結按鈕沒有 custom_id），按下去 `Bot.user_button()` 回只有本人看得到的一句（排在 on_interaction 分派最前面）。改訊息：`change_refused(ledger 那筆, who)`，只有 intent post 而且 from 等於寄件人（`bot/senders.py` 的鍵，見下一項）；card、board（之後走 --board）、其他 intent 都拒。`dcctl-sent.json` 不再決定能不能改，只留給 `bot/pinimport.py`：第一次啟動時（leader，posts.tick 起一個背景工作，每個頻道間隔 `GAP` 秒）查每個文字頻道的釘選，釘著、在 dcctl-sent 或舊的 dcctl-pinned.json 裡、是機器人發的，就記進 ledger（post、from 寫那個頻道的 Claude、pinned），做完在 ledger 旁邊留 `ledger-pins-imported`、把 dcctl-pinned.json 改名成 `.merged`、#audit 一行；中途重啟就重來。ledger 的 `pinned: true` 不受每頻道 500、全部 20000 的清理（每頻道最多 `PINNED_KEEP` 50 則，最舊的先掉），edit 保留旗子，`ledger.pin()` 加或拿掉；dcctl pin／--unpin 寫 `pending.write_pin()`，機器人下一輪 `pending.drain(note, pin)` 套上。保留字首維持 4 個（notice-design 定稿再加）。dcctl 那邊被規則拒收的（保留字首、@everyone／@here、custom_id、ping、edit 改不是自己的或有按鈕卡片的）一律 `refuse()`：原因印到 stderr、結束碼 `REFUSED`＝4（跟太長同類，重送也沒用；manager 11-16）。pinimport 只把 Forbidden／NotFound 當成沒有釘選，其他錯誤往上丟：不留標記、不改名，下次啟動重做。
- **寄件人的鍵 `bot/senders.py`**（C-172a P1d、C-186，manager 11-17）：ledger 的 from 是固定的鍵，顯示時才換成字：`channel:<id>`、`claude:<機器>:<資料夾>`、`program:<機器>:<資料夾>`（`key()`、`parse()`、`label(k, name_of)` 給 `#名稱` 或 `<#id>`、`who()` 頻道的加「的 Claude」）。dcctl 的 `sender_of()`：在機器人那台照 `altention.dc.sender.claude_env()`（往上找 Claude Code、讀它自己的環境）＋`describe()`，窗格經 `sender_channel()` 查頻道（不記窗格號）；別台的 dcctl 在 `botside.hand_over()` 先用 `sender_here()` 查好，經 ssh 帶 `ALTENTION_SENDER`（`sender.encoded()`，base64 JSON），機器人那台只在 `ALTENTION_HANDED` 時讀，讀不到（舊引擎）就是 `program:<這台>:?`，絕不當成頻道。`dcctl whoami` 印鍵和字。機器名三處（dcctl `this_machine()`、`botside.sender_here()`、dc post）一律 `altention.config.this_machine()`（先看指定的名字），同一個寄件人兩個工具算出同一個鍵；舊字裡的主機名轉換時先用 `name_of` 換成清單名，換不到留原樣。dc post 的寄件人：`posts.sender_key()`（寄件頻道，否則 `from_machine`／`from_folder`，舊的從 from_name 括號拿資料夾）。舊的字（「頻道 X 的 Claude（自稱）」「#名稱」「X 上的程式／Claude（f）」）由 `bot/fromkeys.py` 在 posts.tick 第一次知道伺服器時一次轉成鍵（`ledger.rewrite()` 寫進檔案才留 `ledger-from-keys` 標記、#audit 一行轉了幾則留了幾則；同名的多個頻道、找不到的名字、tmux 窗格號留原樣）。轉換之前，`rules.change_refused()` 也把舊字照 `old_key()` 換算再比（dcctl 本地預檢和機器人都是；機器人另給伺服器的頻道名認「#名稱」），自己的訊息不會被結束碼 4 誤拒；轉換後才 drain 的舊 dcctl pending 檔用 `fromkeys.fresh()` 換成鍵（manager 11-17）。同一個系統帳號下兩個變數都能偽造，照 P0-2 的前提只是防呆。
