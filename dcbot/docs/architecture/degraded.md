`TmuxBridge.submit()`）遇到不是 tmux 的頻道，交給 `Bot.queue_turn()`：在自己的 task 排進頻道的 print 佇列（`Bot.locks`），`submit()` 馬上回來（post 的 spool 檔在這時刪，重啟不會重貼、不會再跑一輪；#code-review 擋 7c0ac52）。輪到時頻道已經回到 tmux 的（`!mode `cc_health.binary()`（釘選的舊版還在就用它，否則 `config.CLAUDE`；`tests/test_cc_health` 檢查 bot/ 裡沒有別處寫 `config.CLAUDE`）。測試不讀正式的健康狀態（`tests/tmuxguard` 設 `DCBOT_CC_HEALTH` 指到不存在的檔）。字在 `messages.CC`。**偵測和探測（第二批，`bot/cc_watch.py`、`bot/cc_probe.py`）**：只有 `main.main()` 叫了 `cc_watch.start()` 才動（測試不跑 main，所以不會探測、不寫健康檔）。算失敗的地方：`open()`（這台、機器人開的對話：開不起來或一開就結束 → `tmux`；存的對話接不回、新對話開得起來 →
