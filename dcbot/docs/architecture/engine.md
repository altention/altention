# 跟引擎共用的規則

從 `dcbot/CLAUDE.md` 的「架構」搬來，原文沒改（2026-11-19）。路徑相對於 `dcbot/`；接頭指 `altention/connectors/claude_code/`。

- 只有開發頻道改 `dcbot/`。其他頻道的 Claude 要改引擎的程式，到另一個 git worktree 改（`git worktree add <別的資料夾> -b <分支>`），不要直接改正在跑的那份引擎：它是正式環境，也可能是很多頻道的工作目錄。
- 引擎資料夾裡所有自動化的 git（`deploy.sh`、核心的 `altention/cron_sync.py` 和 `altention/cron_update.py`、`bin/home-pull`，以及透過它的遠端串流連線、用量收集、`apply.py`）共用一把 flock：`.git/altention-git.lock`。同時 pull 會報 `Cannot rebase onto multiple branches`，而一個工作的 `rebase --abort` 會中止另一個工作進行到一半的 rebase。`deploy.sh` 要不要重啟，看的是「這次提交有沒有動到 `dcbot/` 或 `altention/`」（機器人會 import `altention/`，supervisor 的退回也會一起還原它；機器人對 `altention` 的呼叫仍要接住所有例外，見 `remote.inventory()`：別的工作讀的是同一份 `altention/`）（提交前就決定），不看 `HEAD~1..HEAD`，因為共用工作樹裡別的頻道可能剛好在後面又提交了一個。
- 佇列（`state/events/` 的 hook 事件、`state/posts/` 的 altention dc post）都是**處理完才刪**：`events.waiting()`／`postbox.waiting()` 讀出但不刪，處理完 `done(path)`。重啟時處理到一半的那批會再處理一次（最壞重複貼一則），不會掉。posts 是背景處理（同一個寄件者到同一個頻道的照順序，其他並行），`Posts.inflight` 防止同一個檔被撿兩次。`dcremote stream` 也是送出那一行之後才刪。處理時丟例外的事件不會卡在佇列最前面：`events.set_aside()` 把它移到 `state/events-bad/`（留最新 200 個），機器人這邊的 `pump()` 和遠端的 `dcremote relay()` 都一樣；`relay()` 補資料（中途的話、context）失敗時照樣送出原事件，附上 `relay_error`。重啟會等手上的事做完（`Bot.busy_with_work()`：還在交付的 altention dc post、正在貼的事件），最多等 `RESTART_WAIT` 秒，免得 `--new-claude` 這類有副作用的動作重做一次。`dcctl post` 看 `state/heartbeat` 超過 90 秒沒更新，就提示「機器人離線，已排隊，不用重送」。
- `state/`：執行期狀態（不進 git）。`~/.config/altention/secrets/`（token、金鑰）和舊的 `~/.config/dcbot/`，**絕對不要讀、印、改**。
- 同步、`home-pull`、`deploy.sh` 都**不在主工作樹裡 rebase**：有分岔時在 `.git/altention-rebase/` 底下的暫時 worktree 裡把本機的 commit 接到遠端上，再用 `git reset --keep` 把分支移過去（保留各頻道沒提交的修改，只有剛好碰到要合進來的檔案時才拒絕並回報）。被殺掉只會留下可以直接刪的暫時 worktree。主工作樹若還是卡在 rebase 中途（舊工具或人留下的），要 rebase 的工具會寫 `agent-rebase` 記號；同步只中止有這個記號（或超過 30 分鐘的 autostash 殘局）的，中止前先把工作樹裡的修改複製到 `.git/altention-saved/<時間>/`（doctor 會報），沒有記號的當成有人在手動處理；任何同步失敗連續超過 2 小時用 altention dc notify 通知一次。supervisor 退回時的備用 `pull --rebase` 也寫這個記號。
- 引擎共用的設定一律問 `altention/config.py`（只用標準函式庫）：實例在哪、機器清單（沒有實例時讀舊的 `ops/machines.json`，什麼都沒有就當成只有本機一台）、這台叫什麼、機器人在哪台、實例設定（`config.setting("core.…", 預設值)`）。不要再在各處自己讀 `machines.json` 或寫死路徑。讀實例設定要相容：找不到的欄位用預設值，多的欄位忽略（supervisor 退回只動 `dcbot/`，舊版程式會讀到新版的設定）。新寫的介面文字放 `altention/text.py`（之後才好加英文）。`deploy.sh` 也會用系統 Python 跑 `altention/tests`、`chatlog/tests`。
